### 2. DRDoS — 옳은 설명

다음 중 DRDoS 공격에 대한 설명으로 가장 옳은 것은?

1. 공격자가 피해자 시스템에 악성코드를 설치한 후 내부 파일을 암호화하는 공격이다.
2. 공격자가 출발지 IP를 피해자 IP로 위조하여 반사 서버에 요청을 보내고, 반사 서버의 응답이 피해자에게 집중되도록 하는 공격이다.
3. 공격자가 TCP 연결을 정상적으로 완료한 뒤 대량의 HTTP 요청을 전송하는 공격이다.
4. 공격자가 ARP 응답 패킷을 위조하여 동일 네트워크 내 통신을 가로채는 공격이다.

<details>
<summary>정답 보기</summary>

**정답**: 2

**해설**: DRDoS는 Distributed Reflection Denial of Service다. 핵심은 IP 스푸핑 + 반사 서버 + 증폭 응답이다. 공격자는 피해자의 IP로 출발지 주소를 위조하고, DNS/NTP/SSDP/CLDAP 같은 서버에 요청을 보낸다. 그러면 서버의 응답이 공격자가 아니라 피해자에게 몰린다. DRDoS는 그냥 DDoS가 아니라 반사형 DDoS라는 점이 시험 포인트다.

</details>

### 3. DRDoS — 옳지 않은 설명

다음 중 DRDoS 공격에 대한 설명으로 옳지 않은 것은?

1. 공격자는 출발지 IP 주소를 피해자 주소로 위조할 수 있다.
2. 반사 서버는 공격자의 요청에 대한 응답을 피해자에게 전송하게 된다.
3. DNS, NTP, SSDP 등 UDP 기반 서비스가 악용될 수 있다.
4. 피해자가 직접 반사 서버에 요청을 보내야만 공격이 성립한다.

<details>
<summary>정답 보기</summary>

**정답**: 4

**해설**: 피해자가 직접 요청을 보내는 것이 아니다. 공격자가 피해자인 척 요청을 보내고, 반사 서버가 피해자에게 응답을 보내는 구조다. 따라서 4는 DRDoS 구조를 반대로 이해한 보기다.

</details>

### 4. Smurf Attack — 옳은 설명

다음 중 Smurf Attack에 대한 설명으로 가장 옳은 것은?

1. TCP SYN 패킷을 대량으로 보내 서버의 연결 큐를 고갈시키는 공격이다.
2. ICMP Echo Request의 출발지 IP를 피해자 IP로 위조하고, 브로드캐스트 주소로 전송하여 다수의 호스트가 피해자에게 ICMP Echo Reply를 보내도록 하는 공격이다.
3. DNS 서버에 대량의 질의를 보내 도메인 이름 해석을 방해하는 공격이다.
4. 공격자가 사용자 브라우저에서 악성 스크립트를 실행하게 하는 공격이다.

<details>
<summary>정답 보기</summary>

**정답**: 2

**해설**: Smurf Attack은 ICMP 기반 반사/증폭 공격이다. 공격자는 ICMP Echo Request의 출발지 IP를 피해자 IP로 위조하고, 이를 네트워크의 브로드캐스트 주소로 보낸다. 그러면 여러 호스트가 피해자에게 ICMP Echo Reply를 보내 피해자에게 트래픽이 집중된다. Cloudflare도 Smurf 공격을 ICMP 패킷과 스푸핑된 피해자 IP를 이용한 DDoS 공격으로 설명한다.

</details>

### 5. Smurf Attack — 대응 방안

다음 중 Smurf Attack의 대응 방안으로 가장 적절하지 않은 것은?

1. 라우터에서 directed broadcast를 차단한다.
2. 출발지 IP 위조를 줄이기 위해 ingress/egress filtering을 적용한다.
3. ICMP broadcast 요청에 응답하지 않도록 설정한다.
4. 모든 TCP 80번 포트를 차단한다.

<details>
<summary>정답 보기</summary>

**정답**: 4

**해설**: Smurf Attack은 기본적으로 ICMP + 브로드캐스트 + IP 스푸핑과 관련 있다. 따라서 대응은 directed broadcast 차단, ICMP broadcast 응답 제한, IP 스푸핑 방지 필터링이 핵심이다. TCP 80번 포트 차단은 웹 서비스 차단에 가깝고 Smurf Attack의 직접 대응책으로 보기 어렵다.

</details>

### 6. Nmap과 같은 포트 스캔 공격 방어

4. IDS/IPS로는 스캔 공격을 탐지하거나 차단할 수 없다.

<details>

### 9. Snort Rule 분석

다음 Snort Rule에 대한 설명으로 가장 알맞은 것은?

```
alert tcp $HOME_NET [22,80,443] -> any !3389
(msg:"MSTS tunneling attempt";
dsize:>100;
sid:1000001;)
```

1. 내부망에서 외부로 나가는 UDP 패킷 중 목적지 포트가 3389인 경우만 탐지한다.
2. 내부망의 TCP 트래픽 중 출발지 포트가 22, 80, 443이고 목적지 포트가 3389가 아니며 데이터 크기가 100바이트를 초과하면 경고를 발생시킨다.
3. 외부망에서 내부망의 3389번 포트로 들어오는 RDP 접속을 무조건 차단한다.
4. 내부망의 모든 TCP 패킷 중 데이터 크기가 100바이트 이하인 경우 경고를 발생시킨다.

<details>
<summary>정답 보기</summary>

**정답**: 2

**해설**: Snort Rule의 기본 구조는 다음처럼 해석한다.

- `alert`: 탐지 시 경고 발생
- `tcp`: TCP 패킷 대상
- `$HOME_NET`: 출발지 IP
- `[22,80,443]`: 출발지 포트
- `->`: 왼쪽에서 오른쪽 방향
- `any`: 목적지 IP는 임의
- `!3389`: 목적지 포트가 3389가 아님
- `dsize:>100`: 데이터 크기가 100바이트 초과
- `msg`: 탐지 메시지
- `sid`: 룰 식별자

Snort 공식 문서에서도 룰 헤더는 동작, 프로토콜, 네트워크 주소, 포트, 방향을 정의하며, `->` 기준 왼쪽은 출발지, 오른쪽은 목적지다. 또한 포트 선언은 출발지 포트와 목적지 포트로 나뉘어 해석된다.

</details>

### 5. 웹 서버 Access Log 분석

### 4. CCTV 설치·운영

다음 중 CCTV, 즉 고정형 영상정보처리기기 설치·운영에 관한 설명으로 옳지 않은 것은?

1. CCTV를 설치·운영하는 경우 설치 목적, 촬영 범위 및 관리책임자 등을 정보주체가 쉽게 인식할 수 있도록 안내판을 설치하여야 한다.
2. 안내판은 정보주체가 쉽게 확인할 수 있는 장소에 설치하여야 한다.
3. 공개된 장소에 CCTV를 설치하는 경우 법령상 허용 목적에 해당하여야 한다.
4. CCTV 설치 안내표시는 개인정보처리자만 확인할 수 있는 장소에 설치하여도 무방하다.

<details>
<summary>정답 보기</summary>

**정답**: 4

**해설**: CCTV 안내판은 정보주체가 촬영 사실과 목적 등을 쉽게 알 수 있도록 설치해야 한다. 개인정보처리자만 확인 가능한 장소에 두는 것은 취지에 맞지 않는다. 공개된 장소의 고정형 영상정보처리기기는 원칙적으로 제한되며, 범죄 예방·수사, 시설 안전·관리 등 법령상 예외 사유가 있는 경우 설치가 허용된다. 또한 안내판에는 설치 목적·장소, 촬영 범위·시간, 관리책임자 연락처 등이 포함되어야 한다.

</details>

### 5. 아이핀(i-PIN) — 개념

다음 중 아이핀(i-PIN)에 대한 설명으로 가장 옳은 것은?

1. 인터넷상에서 주민등록번호를 직접 입력해야만 본인확인이 가능한 서비스이다.
2. 주민등록번호 없이 온라인에서 본인확인을 할 수 있도록 제공되는 본인확인 수단이다.
3. 아이핀은 오직 공인인증서만을 이용하여 인증한다.
4. 아이핀은 생체인증이나 추가 인증 수단을 사용할 수 없다.

<details>
<summary>정답 보기</summary>

**정답**: 2

**해설**: 아이핀은 주민등록번호를 사용하지 않고 온라인에서 본인확인을 하기 위한 수단이다. KISA 본인확인서비스 안내에서도 아이핀을 주민번호 없이 본인확인할 수 있도록 만들어진 서비스로 설명한다.

</details>

### 6. 아이핀 일반인증 절차

다음 중 아이핀 일반인증 방식의 절차로 가장 적절한 것은?

1. 아이핀 인증창 팝업 → 아이디/비밀번호 입력 → 추가인증 → 인증 완료
2. 아이핀 인증창 팝업 → 주민등록번호 전체 입력 → 인증 완료
3. 아이핀 앱 실행 → QR 스캔 → ARP 인증 → 인증 완료
4. 인증서 제출 → 관리자 승인 → 계정 생성 → 인증 완료

<details>
<summary>정답 보기</summary>

**정답**: 1

**해설**: KISA 안내 기준으로 아이핀 일반인증은 아이핀 인증창 팝업 → ID/PW 입력 → 추가인증 → 인증 완료 흐름이다. 추가인증에는 2차 비밀번호나 생체인증 등이 사용될 수 있다.

</details>

### 7. 아이핀 간편인증(APP)

다음 중 아이핀 간편인증(APP) 방식에 대한 설명으로 가장 옳은 것은?

1. 아이핀 앱을 이용하여 QR코드를 스캔하고, 간편 비밀번호나 생체인증으로 인증할 수 있다.
2. 반드시 주민등록번호와 공동인증서를 동시에 입력해야 한다.
3. 네트워크 장비의 MAC 주소를 기반으로 사용자를 인증한다.
4. 서버의 SSL 인증서만 확인하면 사용자 본인확인이 완료된다.

<details>
<summary>정답 보기</summary>

**정답**: 1

**해설**: 아이핀 간편인증은 앱 기반 인증 방식이다. KISA 안내에 따르면 아이핀 앱에서 QR코드를 스캔하고, PIN 또는 생체인증 등을 통해 인증을 완료할 수 있다.

</details>
