# 4과목 정보보안 일반 최종 한 줄 암기 정리

아래 순서대로 보면 **암호 기초 → 인증/키관리 → 접근통제 → 개인정보 비식별화** 흐름으로 정리됩니다.

## 1. 암호 공격 모델


| 주제        | 최종 한 줄                                                   |
| --------- | -------------------------------------------------------- |
| 암호문 단독 공격 | 공격자가 **암호문만** 가지고 평문이나 키를 추정하는 가장 약한 공격입니다.              |
| 알려진 평문 공격 | 공격자가 **이미 알고 있는 평문-암호문 쌍**을 이용하는 공격입니다.                  |
| 선택 평문 공격  | 공격자가 **원하는 평문을 선택**하고 그 암호문을 얻어 분석하는 공격입니다.              |
| 선택 암호문 공격 | 공격자가 **원하는 암호문을 선택**하고 그 복호 결과를 얻어 분석하는 공격입니다.           |
| 공격 강도 순서  | **암호문 단독 → 알려진 평문 → 선택 평문 → 선택 암호문** 순으로 강해집니다.          |
| 차분 분석     | **평문 쌍의 입력 차이와 암호문 쌍의 출력 차이**를 분석하며, 선택 평문 공격과 연결됩니다.    |
| 선형 분석     | **평문·암호문·키 비트 사이의 선형 관계**를 확률적으로 분석하며, 알려진 평문 공격과 연결됩니다. |

## 2. 블록 암호 운영 모드


| 주제       | 최종 한 줄                                                                 |
| -------- | ---------------------------------------------------------------------- |
| ECB      | 각 블록을 독립 암호화하므로 **같은 평문 블록은 같은 암호문 블록**이 되어 패턴이 노출됩니다.                 |
| CBC      | 이전 암호문과 XOR 후 암호화하며, 오류는 **현재 평문 블록 전체 + 다음 평문 해당 비트**에 전파됩니다.         |
| CFB      | 이전 암호문을 암호화한 값을 피드백하며, 오류는 **현재 평문 해당 비트 + 다음 구간 랜덤 오류**로 나타납니다.       |
| OFB      | 이전 출력값을 피드백해 키스트림을 만들며, 암호문 오류는 **현재 평문 해당 비트만** 영향을 줍니다.              |
| CTR      | 카운터를 암호화해 키스트림을 만들며, **병렬 처리 가능·Nonce/Counter 재사용 금지**가 핵심입니다.         |
| 오류 전파 암기 | **ECB 현재 전체 / CBC 현재 전체+다음 비트 / CFB 현재 비트+다음 랜덤 / OFB·CTR 현재 비트만**입니다. |

## 3. 블록 암호 구조와 국내 알고리즘


| 주제              | 최종 한 줄                                                                     |
| --------------- | -------------------------------------------------------------------------- |
| Feistel 구조      | 블록을 좌우로 나눠 라운드 함수와 XOR·교환을 반복하는 구조로 **DES, SEED, Blowfish, MISTY**와 연결됩니다. |
| SPN 구조          | 치환과 순열/확산을 반복하는 구조로 **AES/Rijndael, ARIA, Square, Serpent**와 연결됩니다.        |
| DES             | 대표적인 대칭키 블록 암호이며 **Feistel 구조**입니다.                                        |
| AES/Rijndael    | 대표적인 대칭키 블록 암호이며 시험에서는 **SPN 계열**로 기억합니다.                                  |
| SEED            | 국내 128비트 블록 암호이며 **Feistel 구조**로 기억합니다.                                    |
| ARIA            | 국내 표준 블록 암호이며 **SPN 계열**로 기억합니다.                                           |
| LEA             | 국내 경량 블록 암호이며 **IoT·저전력·고속 소프트웨어 환경** 키워드와 연결됩니다.                          |
| HIGHT           | 국내 경량 블록 암호이며 **64비트 블록·128비트 키·저자원 환경**으로 기억합니다.                          |
| SHA/RSA/HMAC 구분 | **SHA는 해시, RSA는 공개키, HMAC은 메시지 인증 코드**이므로 Feistel/SPN 분류 대상이 아닙니다.         |

## 4. 디지털 콘텐츠 보호와 정보유출 방지


| 주제        | 최종 한 줄                                          |
| --------- | ----------------------------------------------- |
| 워터마킹      | 콘텐츠 안에 **저작권자·소유자 정보**를 삽입해 소유권과 진위성을 확인합니다.    |
| 스테가노그래피   | **정보가 존재한다는 사실 자체를 숨기는** 은닉 기술입니다.              |
| 디지털 핑거프린팅 | 구매자·배포자별 식별 정보를 삽입해 **불법 유출자 추적**에 사용합니다.       |
| DRM       | 콘텐츠를 암호화하고 **열람·복사·출력·재생 권한과 이용 조건**을 통제합니다.    |
| DLP       | 메일·웹·USB·메신저 등을 통한 **내부 중요정보 유출을 탐지·차단**합니다.    |
| 문서중앙화     | 문서를 중앙 서버에 저장·관리해 **로컬 저장과 무단 반출을 줄이는 방식**입니다.  |
| 공개 SW     | 공개되어 있어도 **라이선스 조건 없이 무조건 수정·재배포 가능한 것은 아닙니다.** |

## 5. 공개키 암호, 전자서명, 인증서


| 주제            | 최종 한 줄                                            |
| ------------- | ------------------------------------------------- |
| 공개키 암호        | 공개키와 개인키 한 쌍을 쓰는 **비대칭키 암호 방식**입니다.               |
| 기밀성 암호화       | 메시지를 숨기려면 **수신자의 공개키로 암호화하고 수신자의 개인키로 복호화**합니다.   |
| 전자서명          | 증명하려면 **송신자의 개인키로 서명하고 송신자의 공개키로 검증**합니다.         |
| 전자서명 제공 속성    | 전자서명은 **무결성·송신자 인증·부인방지**를 제공하지만 기밀성은 제공하지 않습니다.  |
| 해시와 전자서명      | 전자서명은 보통 메시지 전체가 아니라 **메시지 해시값에 대해 서명값을 생성**합니다.  |
| 인증서           | 인증서는 **공개키와 소유자 신원을 CA가 보증한 문서**입니다.              |
| CA            | CA는 인증서에 전자서명하여 **이 공개키가 해당 주체의 공개키임을 보증**합니다.    |
| 그냥 공개키 전송의 위험 | 공개키만 보내면 공격자가 바꿔치기할 수 있으므로 **인증서와 CA 검증**이 필요합니다. |

## 6. CRL / OCSP


| 주제       | 최종 한 줄                                                            |
| -------- | ----------------------------------------------------------------- |
| 인증서 폐지   | 인증서는 유효기간이 남아 있어도 개인키 유출 등으로 **폐지**될 수 있습니다.                      |
| CRL      | CRL은 **폐지된 인증서 목록**이며 핵심 정보는 폐지된 인증서의 **일련번호**입니다.                |
| CRL 오답   | CRL은 폐지된 인증서의 **공개키·개인키·세션키 목록이 아닙니다.**                           |
| OCSP     | OCSP는 특정 인증서의 폐지 상태를 **온라인으로 질의**하는 프로토콜입니다.                      |
| OCSP 상태값 | OCSP 인증서 상태값은 **good / revoked / unknown**이고, **bad는 상태값이 아닙니다.** |
| 만료와 폐지   | 만료 여부는 인증서 유효기간 필드로 확인하고, 폐지 여부는 **CRL/OCSP**로 확인합니다.             |


---

## 7. OTP / HSM / 인증 방식


| 주제        | 최종 한 줄                                                      |
| --------- | ----------------------------------------------------------- |
| 지식기반 인증   | 사용자가 **알고 있는 것**으로 인증하며 ID/PW, PIN이 대표적입니다.                 |
| 소유기반 인증   | 사용자가 **가지고 있는 것**으로 인증하며 OTP 토큰, 인증서 저장매체 등이 대표적입니다.        |
| 생체기반 인증   | 사용자의 **신체 특징**으로 인증하며 지문, 홍채, 얼굴이 대표적입니다.                   |
| OTP       | OTP는 매번 달라지는 **일회용 비밀번호**로, 공개키 암호 방식이 아닙니다.                |
| HOTP/TOTP | HOTP는 **카운터 기반**, TOTP는 **시간 기반** OTP입니다.                   |
| 거래연동 OTP  | 계좌번호·금액 등 **거래정보와 연동**해 OTP를 생성합니다.                         |
| HSM       | HSM은 **암호키·개인키를 안전하게 보관하고 내부에서 암호 연산을 수행하는 하드웨어 보안 모듈**입니다. |
| HSM 오해 방지 | HSM은 인증서 관리 서버 자체가 아니라 **개인키와 암호키를 밖으로 꺼내지 않게 보호하는 장치**입니다. |


---

## 8. 해시 / MAC / HMAC


| 주제              | 최종 한 줄                                                                            |
| --------------- | --------------------------------------------------------------------------------- |
| 해시              | 임의 길이 데이터를 고정 길이 **메시지 다이제스트**로 바꾸며, 주로 무결성 확인에 사용합니다.                            |
| 해시 한계           | 해시만으로는 공격자가 메시지와 해시값을 함께 바꿀 수 있어 **송신자 인증과 부인방지**가 안 됩니다.                         |
| MAC             | MAC은 **메시지 + 공유 비밀키**로 생성하는 메시지 인증 코드입니다.                                         |
| MAC 제공 속성       | MAC은 **무결성·메시지 인증**을 제공하지만 기밀성과 부인방지는 제공하지 않습니다.                                  |
| HMAC            | HMAC은 **해시 함수와 공유 비밀키를 이용한 MAC**입니다.                                              |
| HMAC 오해 방지      | HMAC은 기존 MAC 값을 다시 해시하는 것이 아니라 **해시 함수 구조로 MAC 값을 생성하는 방식**입니다.                   |
| MAC vs 접근통제 MAC | HMAC의 MAC은 Message Authentication Code이고, 접근통제의 MAC은 Mandatory Access Control입니다. |
| 전자서명 비교         | 부인방지는 공유키 기반 MAC/HMAC이 아니라 **송신자 개인키 기반 전자서명**과 연결됩니다.                            |

## 9. SSL / TLS


| 주제        | 최종 한 줄                                                         |
| --------- | -------------------------------------------------------------- |
| TLS       | TLS는 통신 중 데이터의 **기밀성·무결성·서버 인증**을 제공하는 보안 프로토콜입니다.             |
| HTTPS     | HTTPS는 **HTTP over TLS**이고 기본 포트는 **443**입니다.                  |
| TLS 보호 범위 | TLS는 **통신 중 데이터**를 보호하지, 통신 전·후 저장 데이터를 자동으로 보호하지 않습니다.        |
| TLS 인증서   | 서버 인증서는 **서버 공개키와 도메인 신원을 CA가 보증**한 것입니다.                      |
| TLS 키 사용  | TLS는 인증서/공개키로 서버를 확인하고, 실제 데이터는 보통 **세션키 기반 대칭키 암호**로 보호합니다.   |
| TLS 오답    | HTTPS/TLS가 있다고 해서 **기업의 윤리성·사이트의 선의·DB 저장 암호화**를 보장하는 것은 아닙니다. |
| ECDHE 역할  | TLS에서 ECDHE는 실제 데이터를 암호화하는 것이 아니라 **세션키 재료인 공유 비밀값을 합의**합니다.   |


---

## 10. Needham-Schroeder / Kerberos / KDC


| 주제                    | 최종 한 줄                                                               |
| --------------------- | -------------------------------------------------------------------- |
| KDC                   | KDC는 사용자와 서비스 사이에 필요한 **세션키와 티켓을 분배하는 신뢰된 제3자 서버**입니다.               |
| Needham-Schroeder     | Needham-Schroeder는 KDC가 Alice-Bob 사이의 **세션키를 분배하는 대칭키 기반 원형 모델**입니다. |
| Needham-Schroeder 취약점 | 오래된 티켓이 재사용될 수 있는 **재전송 공격** 문제가 핵심입니다.                              |
| Kerberos              | Kerberos는 **KDC 기반·대칭키 기반·티켓 기반 인증 프로토콜/시스템**입니다.                    |
| Kerberos와 전자서명        | Kerberos는 전자서명이 아니며 **공개키 기반 부인방지 프로토콜이 아닙니다.**                      |
| AS                    | AS는 사용자 최초 인증 후 **TGT**를 발급합니다.                                      |
| TGS                   | TGS는 TGT를 확인하고 실제 서비스 서버용 **Service Ticket**을 발급합니다.                 |
| TGT                   | TGT는 실제 서비스 서버가 아니라 **TGS에게 서비스 티켓을 요청할 때 쓰는 티켓**입니다.                |
| Service Ticket        | Service Ticket은 실제 서비스 서버에 제출하는 **접근용 티켓**입니다.                       |
| 티켓 구조                 | 티켓은 공개키 인증서가 아니라 보통 **서비스 서버와 KDC의 공유 대칭키로 암호화된 정보**입니다.             |
| Nonce/Timestamp       | 난수와 타임스탬프는 **신선성 확인과 재전송 공격 대응**에 사용됩니다.                             |

## 11. Diffie-Hellman / Blom / 키 분배


| 주제             | 최종 한 줄                                                           |
| -------------- | ---------------------------------------------------------------- |
| Diffie-Hellman | DH는 공개값을 교환하고 각자의 개인값을 이용해 **같은 공유 비밀값을 계산하는 키 합의 방식**입니다.       |
| DH 개인값         | DH에서 **개인값은 비밀로 유지**하고, 공개값은 네트워크로 교환할 수 있습니다.                   |
| DH 계산          | 공유 비밀값은 **자신의 개인값 + 상대방의 공개값**으로 계산합니다.                          |
| DH 한계          | 기본 DH는 상대 인증이 없어 **중간자 공격에 취약**할 수 있습니다.                         |
| DH 제공 속성       | DH 단독은 데이터 직접 암호화, 무결성, 인증, 전자서명, 부인방지를 제공하지 않고 **키 합의만 수행**합니다. |
| TLS에서 DH       | TLS의 ECDHE는 인증서와 결합되어 **세션키 재료 합의**에 사용됩니다.                      |
| Blom 방식        | Blom은 신뢰기관이 사전에 키 재료를 나눠주고 사용자 쌍이 공통키를 계산하는 **사전 키 분배 방식**입니다.   |
| KDC vs Blom    | KDC는 통신 시점에 세션키/티켓을 발급하고, Blom은 **사전 배포된 정보로 쌍별 키를 계산**합니다.      |

## 12. 접근통제 원칙과 모델


| 주제            | 최종 한 줄                                                        |
| ------------- | ------------------------------------------------------------- |
| 접근통제          | 접근통제는 **주체가 객체에 어떤 권한으로 접근할 수 있는지 통제**하는 것입니다.                |
| 주체            | 주체는 접근을 요청하는 **사용자·프로세스·프로그램**입니다.                            |
| 객체            | 객체는 접근 대상인 **파일·DB·서버·자원**입니다.                                |
| 접근권한          | 접근권한은 **읽기·쓰기·실행·삭제** 같은 행위입니다.                               |
| 최소 권한         | 최소 권한은 업무 수행에 필요한 **최소한의 권한만 부여**하는 원칙입니다.                    |
| Need-to-know  | Need-to-know는 사용자가 **알아야 할 필요가 있는 정보만** 접근하게 하는 원칙입니다.        |
| 직무분리          | 직무분리는 중요한 업무를 여러 역할로 나눠 **부정행위와 오류를 줄이는 원칙**입니다.              |
| 정책            | 정책은 접근 허용/거부를 결정하는 **규칙과 기준**입니다.                             |
| 메커니즘          | 메커니즘은 정책을 실제 시스템에서 집행하는 **기술적 수단**입니다.                        |
| DAC           | DAC는 객체 소유자가 권한을 부여하는 **임의적 접근통제**입니다.                        |
| MAC           | MAC은 보안등급과 정책에 따라 시스템이 강제하는 **강제적 접근통제**입니다.                  |
| RBAC          | RBAC는 사용자 역할에 따라 권한을 부여하는 **역할 기반 접근통제**입니다.                  |
| Bell-LaPadula | Bell-LaPadula는 **기밀성 모델**이며 No Read Up, No Write Down이 핵심입니다. |
| Biba          | Biba는 **무결성 모델**이며 No Read Down, No Write Up이 핵심입니다.          |
| Clark-Wilson  | Clark-Wilson은 **상업적 무결성, 직무분리, 잘 형성된 트랜잭션, 감사**가 핵심입니다.       |
| Chinese Wall  | Chinese Wall은 **이해상충 방지**를 위해 과거 접근 이력에 따라 접근을 제한합니다.         |

## 13. 비식별화 처리기법


| 주제        | 최종 한 줄                                                     |
| --------- | ---------------------------------------------------------- |
| 비식별화      | 비식별화는 특정 개인을 알아볼 수 없도록 **식별 가능성을 낮추는 처리**입니다.              |
| 가명처리      | 가명처리는 식별 가능한 값을 **다른 값으로 대체**하는 방식이며 암호화가 세부기술로 나올 수 있습니다. |
| 총계처리      | 총계처리는 개인별 값을 **합계·평균·라운딩·재배열 등 통계값**으로 바꾸는 방식입니다.          |
| 데이터 삭제    | 데이터 삭제는 식별자나 레코드 일부/전체를 **삭제**하는 방식입니다.                    |
| 데이터 범주화   | 범주화는 35세를 30대로 바꾸는 것처럼 구체값을 **범위·구간**으로 바꾸는 방식입니다.         |
| 데이터 마스킹   | 마스킹은 홍길동을 홍**, 전화번호를 010-****-1234처럼 **일부를 가리는 방식**입니다.    |
| 기출 67번 대응 | 가명처리 방법을 묻고 **암호화**가 있으면 우선 암호화를 고릅니다.                     |

# 시험 직전 압축 암기 20줄

정말 시간이 없으면 아래 20줄만 보시면 됩니다.

```text
1. 공격 강도: 암호문 단독 → 알려진 평문 → 선택 평문 → 선택 암호문
2. 차분 분석 = 입력/출력 차이, 선택 평문 공격
3. 선형 분석 = 평문·암호문·키 비트 선형 관계, 알려진 평문 공격
4. ECB = 패턴 노출, CBC = 현재 전체+다음 비트
5. CFB = 현재 비트+다음 랜덤, OFB/CTR = 현재 비트만
6. DES/SEED = Feistel, AES/ARIA = SPN
7. 워터마킹 = 저작권, 핑거프린팅 = 유출자 추적, 스테가노그래피 = 존재 은닉
8. DRM = 이용권한 통제, DLP = 유출 탐지·차단
9. 암호화 = 수신자 공개키, 서명 = 송신자 개인키
10. 인증서 = 공개키와 신원을 CA가 보증
11. CRL = 폐지 인증서 일련번호, OCSP = good/revoked/unknown
12. OTP = 일회용 비밀번호, 공개키 방식 아님
13. HSM = 하드웨어 키 보호 + 암호 연산
14. 해시 = 무결성 확인용 요약값, 키 없음
15. MAC/HMAC = 공유키 기반 무결성 + 메시지 인증, 기밀성/부인방지 X
16. TLS = 통신 중 기밀성·무결성·서버 인증, 저장 데이터 자동 보호 X
17. Kerberos = KDC 기반 대칭키 티켓 인증
18. AS = TGT, TGS = Service Ticket
19. DH = 공유 비밀값 합의, 단독 사용 시 MITM 취약
20. BLP = 기밀성, Biba = 무결성, Clark-Wilson = 상업적 무결성, Chinese Wall = 이해상충
```
