# 패킷 (Packet) — 택배로 이해하는 네트워크 단위

> 출처: YouTube [IT 인프라] 03. 택배를 알면 패킷이 보인다 (스크립트 원본: `03.packet.md`)

핵심 명제: **패킷은 택배다.** 네트워크에서 데이터를 주고받는 일은 택배로 물건을 보내는 일과 동형(同型)이다. 이 비유 하나로 패킷의 구조, 운송 인프라, 보안 장비, 망 중립성까지 일관되게 설명할 수 있다.

---

## 1. 시나리오 — 철수가 영희에게 선물을 보낸다

### 1.1 발신 측: 포장 (Encapsulation)

철수는 영희에게 선물을 보내려 한다. 선물은 **목적**, 택배는 **수단**이다.

포장 절차:

1. 선물을 **뽁뽁이**로 감싼다.
2. 뽁뽁이로 감싼 선물을 **박스**에 넣는다.
3. 박스에 **송장**을 붙인다. 송장에는 **송신자/수신자 각각의 이름과 주소**가 기재된다.

송장 정보의 중요도는 입장에 따라 다르다.

| 정보 | 누구에게 중요한가 | 언제 중요한가 |
|------|----------------|-------------|
| 수신자 정보 | 택배 기사 | 평상시 (가장 중요) |
| 송신자 정보 | 택배 기사 | 배송 실패 시 (반송 필요) |
| 송신자 정보 | 영희 | 잘 받았을 때 (누가 보냈는지 확인) |

### 1.2 운송 구간

철수가 택배 기사에게 박스를 인계하는 순간, 철수의 통제권은 끝난다 ("내 손을 떠난 거죠"). 이후 트럭·기사·물류 회사가 박스를 영희네 집 현관까지 운반한다.

### 1.3 수신 측: 개봉 (Decapsulation)

박스가 영희네 집에 도착한다. 가족 중 누가 받느냐에 따라 처리가 달라진다. 가령 어머니가 받아 송장을 본 후 "철수가 보낸 거네"라고 판단해 통과시키거나 거절할 수 있다. 어머니가 박스를 뜯어 내용물까지 확인할 수도 있다 (이 경우 사생활 문제가 발생).

영희가 박스를 받으면 **선물(목적)을 취하고 박스(수단)는 폐기**한다.

## 2. 비유 매핑 — 택배와 네트워크의 대응

| 택배 세계 | 네트워크 세계 | 비고 |
|----------|------------|------|
| 선물 | 페이로드 (Payload) | 실제 전달할 데이터 |
| 송장 | 헤더 (Header) | 메타정보 (주소·식별자) |
| 송장 붙은 박스 | 패킷 (Packet) | L3 단위, 헤더 + 페이로드 |
| 뽁뽁이로 감싼 선물 | 세그먼트 (Segment) | L4 단위, 패킷에 들어가기 전 형태 |
| 철수네/영희네 집 | 호스트 (Host) / 엔드포인트 (Endpoint) | 네트워크 인프라의 이용자 |
| 현관 | NIC (Network Interface Card) / 게이트웨이 (Gateway) | 호스트의 출입구 |
| 두 집 사이 경로 | 네트워크 구간 | 운송 경로 (Path) |
| 택배 회사·기사·트럭 | ISP (Internet Service Provider) | KT, SKB, LG U+ 등 |
| 송장의 **주소** | IP 주소 (IPv4) | 호스트 식별 |
| 송장의 **이름** | 포트 번호 (Port) | 엔드포인트 도착 후 프로세스 식별 |
| 가족 구성원 (영희, 동생, 아빠) | 프로세스 (Process) | 통신의 실제 주체 |

핵심 통찰: **통신의 주체는 컴퓨터가 아니라 프로세스다.** IP가 호스트까지 안내하고, 포트가 프로세스를 지목한다.

## 3. 패킷의 구조와 크기

### 3.1 단위 의식

패킷은 **물류 단위**다. 크기 제한이 있다.

- **MTU (Maximum Transmission Unit)**: 이더넷 기준 **1500 bytes**
- 큰 데이터는 MTU에 맞게 **잘게 쪼개진** 형태로 전송된다 → 패킷 = "조각난 데이터"

### 3.2 1500 bytes의 내부 구성

```
┌─────────────┬──────────────────────────────────────────────────┐
│  Header     │                Payload                           │
│   40 B      │                1460 B                            │
│ (IP20+TCP20)│                                                  │
└─────────────┴──────────────────────────────────────────────────┘
                        총 1500 bytes (MTU)
```

| 영역 | 크기 | 구성 |
|------|------|------|
| IP 헤더 (L3) | 20 B | 옵션 없을 때 최소 크기 |
| TCP 헤더 (L4) | 20 B | 옵션 없을 때 최소 크기 |
| 페이로드 (Data) | 1460 B | 실제 데이터 영역 |
| **합계** | **1500 B** | MTU |

> 헤더 40 B vs 페이로드 1460 B — 비율로 보면 헤더는 매우 작다. 그림으로 표현할 때 둘을 같은 크기로 그리면 오해를 부른다.

### 3.3 TCP/IP 표기 관례

`TCP/IP`에서 슬래시(`/`)를 쓰는 이유: **TCP는 L4, IP는 L3**로 계층이 다르기 때문이다. 함께 쓰이지만 성격이 다르므로 분리해 표기한다.

## 4. 캡슐레이션 — 데이터가 패킷이 되는 과정

```
[ Payload ]                          ← 원본 데이터 (선물)
    ↓ + L4 Header (TCP)
[ TCP Header | Payload ]             ← Segment (뽁뽁이로 감싼 선물)
    ↓ + L3 Header (IP)
[ IP Header | TCP Header | Payload ] ← Packet (송장 붙은 박스)
    ↓ 전송
```

| 동작 | 의미 | 비유 |
|------|------|------|
| **Encapsulation** | 상위 계층 데이터를 하위 계층 헤더로 감싸기 | 선물을 뽁뽁이로, 다시 박스로 포장 |
| **Decapsulation** | 하위 계층 헤더를 벗겨 상위 계층 데이터 추출 | 박스 → 뽁뽁이 → 선물 순으로 개봉 |

> 마트료시카 인형처럼 인형 속의 인형이 들어 있는 구조. 한 계층씩 감싸고 한 계층씩 벗긴다.

**용어 주의**: 세그먼트와 패킷의 포함 관계는 "세그먼트가 패킷 안으로 들어간다". 뽁뽁이로 싼 물건이 박스 속에 들어가는 것과 같다.

## 5. 보안 장비 — 어디까지 들여다보는가

영희 엄마가 박스를 어떻게 다루는지에 따라 비유가 달라진다.

### 5.1 검사 깊이별 분류

| 검사 깊이 | 장비/기법 | 무엇을 보는가 | 비유 |
|---------|----------|-------------|------|
| L3/L4 헤더 | **방화벽 (Packet Filtering Firewall)** | 송장(헤더)만 | 엄마가 송장만 보고 통과/거절 |
| L7 헤더까지 | **SPI** (Shallow Packet Inspection)¹ | 박스 살짝 열어 안쪽 헤더 확인 | 박스 살짝 열어봄 (Shallow Copy 비유) |
| 페이로드 본문 | **DPI** (Deep Packet Inspection) → **IPS** | 데이터 본문까지 모두 | 박스 완전히 뜯어 내용물 확인 (Deep Copy 비유) |

¹ **용어 주의**: 강의에서 SPI는 Shallow Packet Inspection의 의미로 사용된다 (딥카피/셸로우카피 비유). 일반 보안 분야에서 약어 "SPI"는 통상 **Stateful** Packet Inspection을 가리키므로 문헌에 따라 의미가 다를 수 있다.

### 5.2 처리 결과

방화벽이 헤더를 보고 내릴 수 있는 결정:
- **Bypass / Accept**: 통과시킴 → 패킷이 목적지 프로세스에 도달
- **Drop / Reject**: 폐기 → 수신 프로세스는 패킷을 받지 못함

### 5.3 법적 이슈 — 누가 페이로드를 들여다볼 수 있는가

페이로드는 **사생활 영역**이다. 헤더(송장)는 운송에 필요하지만, 페이로드(선물 내용)는 운송업자가 볼 권리가 없다.

| 주체 | DPI 수행 시 | 근거 |
|------|-----------|------|
| ISP (KT, SKB 등) | **불법** | 정보통신비밀보호법 위반 (통신 비밀 침해) |
| 회사 내부망 | 일반적으로 허용 | 회사 자원·업무 시간에 발생한 통신, 회사가 정보 소유권 주장 가능² |

² 단, 회사의 DPI도 목적·범위·저장 여부에 따라 논란의 여지가 있다.

핵심 원칙: **운송 회사는 운송만 한다.** 마약·폭발물 운반 방지를 명분으로 모든 택배를 전수 검열하는 것은 모든 발신자를 잠재 범죄자로 간주하는 위험한 행위이며, 동시에 사생활을 침해한다.

## 6. 망 중립성 (Network Neutrality)

ISP는 **운송하는 데이터의 종류·내용에 따라 차별할 수 없다**.

| 비유 | 네트워크 |
|------|---------|
| 택배사가 "절임배추는 무거우니 안 받아요" | ISP가 특정 데이터 유형을 차별 |
| 택시가 손님을 골라 태우는 승차거부 | 특정 트래픽 차단·속도 저하 |

대표 사례 — ISP가 카카오톡 보이스톡 트래픽을 차단·제한한다면 망 중립성 위반이다.

원리: 운송업자(ISP)의 본업은 **유통**이지 콘텐츠 선별이 아니다.

> **보충 통찰 (강의 미명시)**: 콘텐츠 기반 차별은 페이로드 검사를 전제하므로, 기술적으로는 §5.3의 사생활 침해 이슈와도 연결된다. 단, 강의는 두 주제(망 중립성 / DPI)를 별도로 다루며 둘 사이의 인과 사슬을 명시적으로 결합하지는 않는다.

## 7. 정리 — 한 장 요약

```
패킷 = 네트워크의 택배 박스 (L3 단위)

┌──────────────────────────────────────────────┐
│ 헤더 (송장) │       페이로드 (선물)           │
│   40 B      │         1460 B                  │
└──────────────────────────────────────────────┘
              ↑ MTU 1500 B 제한 → 데이터는 조각난다
```

핵심 명제 5가지:

1. 패킷은 **L3 단위**, 세그먼트는 **L4 단위**. 세그먼트가 패킷 안에 들어간다 (캡슐레이션).
2. 헤더는 **메타정보**(주소·포트), 페이로드는 **본 데이터**.
3. IP는 **호스트**를 식별, 포트는 호스트 도착 후 **프로세스**를 식별.
4. 보안 장비는 **검사 깊이**로 구분 — 헤더만(방화벽), L7 헤더까지(SPI=Shallow), 페이로드까지(DPI/IPS).
5. ISP는 **운송**만 한다 — 페이로드를 들여다보면 사생활 침해, 콘텐츠로 차별하면 망 중립성 위반.

## 부록 — 용어 색인

| 약어 | 풀네임 | 의미 |
|------|--------|------|
| MTU | Maximum Transmission Unit | 한 번에 전송 가능한 최대 크기 (이더넷 1500 B) |
| NIC | Network Interface Card | 호스트의 네트워크 인터페이스 (현관) |
| ISP | Internet Service Provider | 인터넷 회선 사업자 (택배 회사) |
| IP | Internet Protocol | L3 프로토콜, 호스트 주소 체계 |
| TCP | Transmission Control Protocol | L4 프로토콜, 신뢰성 있는 전송 |
| DPI | Deep Packet Inspection | 페이로드까지 검사 |
| SPI | Shallow Packet Inspection (강의 맥락) / Stateful Packet Inspection (일반 보안 표준) | 약어 충돌 주의 |
| IPS | Intrusion Prevention System | DPI 기반 침입 방지 시스템 |
