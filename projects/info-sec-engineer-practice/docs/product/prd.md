# PRD: 정보보안기사 실기 복습 문제 앱

## 1. 개요

- 문제 정의: 대화로 학습한 정보보안기사 실기 내용을 다시 꺼내고 검증할 수 있는 반복 가능한 문제 환경이 없다. 기존 문서·기출 데이터·offline Lab은 존재하지만, 단계별 즉시 피드백과 진행도 보존을 제공하는 학습 UI는 없다.
- 대상 사용자: 정보보안기사 실기를 준비하는 이 vault의 개인 학습자.
- 핵심 가치: 근거가 추적되는 문제를 단계별로 반복하고, 정답이 명확한 답은 즉시 확인하며, 서술형은 모범 답안과 채점 기준으로 스스로 보정한다.
- 프로젝트 유형: 기존 학습 vault 확장(brownfield).
- V1 계획 범위: Chapter 2 P1 네트워크·방화벽 설정형과 Chapter 3 P1 서비스 보안설정(웹·DNS·메일·DB·Secure SDLC) 축의 근거 기반 문항.
- 현재 앱 범위: V1 계획 범위와 별개로, 현재 활성 curriculum은 1장 P1 시스템 보안, 2장 네트워크·방화벽, 3장 P1 서비스 보안설정, 5장 P1 관리·위험관리·업무연속성·침해사고·포렌식·개인정보 기초를 포함한다. 현재 콘텐츠 범위는 `projects/info-sec-engineer-practice/data/curriculum.json`, 기능 범위는 직접 구현·계약 테스트를 기준으로 확인하며, 이 PRD의 V1 요구사항을 소급해 바꾸지 않는다.

## 2. 기능 요구사항

| ID | 요구사항 | 수용 기준 | 우선순위 |
|---|---|---|---|
| FR-1 | 학습자는 학습 경로와 원본 장/절 두 기준으로 문제를 탐색할 수 있다. | V1에서 각 문항은 `네트워크·장비·공격` 또는 `서비스 보안설정` 경로와 해당 2장·3장 원본 위치를 함께 가진다. | Must |
| FR-2 | 앱은 실기형 단답, 빈칸, 순서 배열, 패킷/룰 판정, 설정 복합형 문제를 제공한다. | 객관식 없이 각 유형을 제공하고, 복합형은 여러 결정적 빈칸을 하나의 설정·판독 시나리오로 묶으며 각 문항은 단계·선수 개념을 가진다. | Must |
| FR-3 | 정답이 결정적인 문제는 브라우저에서 자동 채점한다. | 채점은 문항별 허용 정답 집합과 유형별 정규화 규칙으로 재현 가능하며, 채점 결과·정답·해설을 즉시 표시한다. | Must |
| FR-4 | 서술형은 자가 채점한다. | 제출 후 모범 답안, 키워드 충족률, 누락 키워드, 감점 위험, 근거 상태를 표시하고 학습자가 `이해함/복습 필요`를 기록할 수 있다. 키워드 충족률은 정오답 판정이 아니다. | Must |
| FR-5 | 모든 문항은 문제의 사실 근거와 검증 상태를 표시한다. | 각 문항은 최소 하나의 source path와 `official / source-derived / inferred` 상태를 가지며, 원문 미검증 복원 문제는 화면에서 구분된다. | Must |
| FR-6 | 학습자는 진행도와 오답 상태를 보존·초기화·재풀이할 수 있다. | 문항별 풀이 여부·최근 결과·정답 완료 상태·자가평가를 브라우저 LocalStorage에 저장하고, 문항·주제·전체 단위 초기화 및 재풀이를 제공한다. | Must |
| FR-7 | 새 문제를 UI 코드 수정 없이 추가할 수 있다. | 문제 데이터 파일 추가와 curriculum 참조만으로 새 주제·단계를 노출할 수 있고, 데이터 validator가 필수 메타데이터·ID·정답 구조를 검증한다. | Must |
| FR-8 | 별도 Practical Labs 프로젝트와 충돌하지 않고 연결될 수 있다. | 문항은 선택적으로 명시적인 외부 Lab reference를 가질 수 있으며, 브라우저 앱은 시스템 명령·네트워크 변경을 수행하지 않는다. | Should |
| FR-9 | 학습자에게 기출 기반·예상·학습 문항을 구분해 보여 준다. | 학습 모드에서 실제 회차 참조 문항은 기출 기반, `questionKind: predicted` 문항은 예상 문제로 표시한다. 예상 문제에는 예측 목록과 패턴 분석 근거가 모두 있어야 한다. | Must |
| FR-10 | 학습자에게 단서를 줄이는 실전 풀이 흐름을 제공한다. | 실전 모드에서는 주제·단계·문항 분류·상세 입력 라벨을 숨기고, 정의된 실전 지문만 노출한다. | Must |

## 3. 비기능 요구사항

| ID | 요구사항 | 기준 |
|---|---|---|
| NFR-1 | 오프라인성 | `file://` 또는 정적 파일 서버에서 외부 API·네트워크 요청 없이 동작한다. |
| NFR-2 | 정확성 | 자동 채점 문항은 모호한 자유서술을 사용하지 않으며, source path·검증 상태·해설을 모두 가진다. |
| NFR-3 | 일관성 | 단일 Question schema와 렌더러를 사용하고, 단계·정답 표시·근거 표시 UX가 모든 주제에서 동일하다. |
| NFR-4 | 멱등성 | 앱 재실행과 문제 재풀이가 문제 은행을 변경하지 않으며, 초기화는 사용자 진행도만 삭제한다. |
| NFR-5 | 사용성·접근성 | 키보드로 답 입력·제출·다음 문항 이동이 가능하고, 코드 블록·정답 상태·오답 근거를 시각적으로 구분한다. |
| NFR-6 | 확장성 | 장·학습 경로·문제 유형·근거 상태가 하드코딩되지 않은 데이터 모델로 표현된다. |
| NFR-7 | 배포 이행성 | 프레임워크·서버 의존 없이 정적 호스팅으로 옮길 수 있다. |

## 4. 에픽

### Epic 1: 검증 가능한 학습 콘텐츠 기반

- 의존성: 없음
- 스토리:
  - 1.1 장/절과 학습 경로를 함께 표현하는 curriculum 정의
  - 1.2 문제·정답·근거·검증 상태를 표현하는 Question schema
  - 1.3 문제 은행 정적 validator와 오류 보고

### Epic 2: 정적 실기 문제 플레이어

- 의존성: Epic 1
- 스토리:
  - 2.1 학습 경로·장/절 탐색과 진행도 요약
  - 2.2 단답·빈칸·순서·판정 문제 렌더링과 자동 채점
  - 2.3 서술형 자가 채점 카드와 근거 표시
  - 2.4 재풀이·LocalStorage 진행도·초기화

### Epic 3: 네트워크·방화벽 파일럿 콘텐츠

- 의존성: Epic 1, Epic 2
- 스토리:
  - 3.1 Cisco ACL과 wildcard/in-out 문제 세트
  - 3.2 Ingress/Egress filtering·uRPF 문제 세트
  - 3.3 iptables chain·옵션·target·상태/로그 문제 세트
  - 3.4 directed broadcast와 Smurf 대응 문제 세트

### Epic 4: 서비스 보안설정 콘텐츠와 품질 검증

- 의존성: Epic 2, Epic 3
- 스토리:
  - 4.1 HTTP·웹 취약점·Apache/IIS/WAF 설정 문항
  - 4.2 DNS·메일·DB 감사·Secure SDLC 설정 문항
  - 4.3 데이터 validator와 브라우저 흐름 검증, 기존 Lab/기출 데이터 참조 무결성 확인
  - 4.4 1·4·5장 문제 팩 추가 안내와 템플릿 문서화

## 5. V1 계획 기준 MVP 범위

- 포함:
  - 별도 `projects/info-sec-engineer-practice/` 정적 앱
  - 2장 네트워크·방화벽 및 3장 서비스 보안설정 문제 은행
  - 자동 채점 가능한 실기형 문항과 자가 채점 서술형
  - 근거·검증 상태·진행도·재풀이
  - 데이터 검증 스크립트
- 제외:
  - 실제 iptables/Cisco 장비 명령 실행
  - 외부 LLM 기반 서술형 자동 채점
  - 계정·서버 동기화·다중 사용자 기능
  - V1에서 1~5장 전 범위의 완성된 문제 콘텐츠

## 6. 기술 제약

- 브라우저에서 바로 여는 정적 HTML/CSS/JavaScript로 구현한다.
- 외부 라이브러리, API, 서버, 데이터베이스를 V1에 추가하지 않는다.
- 문제와 curriculum은 사람이 검토 가능한 JSON 원본으로 관리하고, 직접 파일 열기 환경을 위해 검증·생성된 browser-loadable data script를 함께 둔다.
- 원본 학습 노트와 기출 데이터셋은 read-only source로 취급하고, 앱은 `projects/info-sec-engineer-practice/` 아래 별도 산출물로 둔다.
- 진행도는 버전이 부여된 LocalStorage 키에만 저장한다. 저장소 사용 불가 시에도 문제 풀이와 정답 확인은 가능해야 한다.
