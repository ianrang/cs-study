# 정보보안기사 실기 2026년 2회 대비 시험용 통합 학습본

## 사용법
이 문서는 PDF 원문을 순서대로 요약한 문서가 아니다. 시험 합격에 필요한 내용을 기출 빈도, 최근성, 출제기준, 답안 작성 가능성 기준으로 재구성한 읽기형 통합본이다.

공부할 때는 각 단원을 다음 순서로 읽는다.

1. 왜 중요한지 읽는다.
2. 개념을 이해한다.
3. 같이 묶어 외울 항목을 본다.
4. 시험에서 어떻게 바뀌어 나오는지 확인한다.
5. 3단 답안으로 직접 써 본다.

서술형 답안은 모두 하나의 템플릿으로 통일한다.

`무엇인가 → 왜 중요한가/문제인가 → 어떻게 적용·대응하는가`

이 템플릿은 개념형, 공격형, 설정형, 로그형, 법규형, 비교형에 모두 적용한다. 길게 쓰려고 하지 말고, 세 칸을 빠뜨리지 않는 것이 목표다.

## P1-1. 위험관리와 위험평가

### 왜 중요한가
위험관리/위험평가는 1~30회 전체에서 가장 반복성이 강한 축이다. 관리·법규 문제로도 나오고, 시스템이나 개인정보 문제의 판단근거로도 쓰인다. 시험에서는 단순히 “위험이란 무엇인가”를 묻기보다 자산, 위협, 취약점, 영향, 대응전략을 연결해 묻는다.

### 이해하기
위험은 보호해야 할 자산에 위협이 작용하고, 그 위협이 취약점을 통해 실제 영향을 만들 가능성이다. 그래서 위험분석은 자산을 식별하고, 자산에 대한 위협과 취약점을 찾고, 발생 가능성과 영향을 평가하는 과정이다.

정량적 분석은 금액이나 확률처럼 수치로 위험을 계산하려는 방식이다. SLE, ARO, ALE 같은 용어가 여기에 연결된다. 정성적 분석은 전문가 판단, 등급, 체크리스트, 델파이 기법처럼 수치화가 어려운 상황에서 상대적 우선순위를 정한다. 기준선 접근법은 기본 보호대책을 빠르게 적용하는 방식이고, 상세 위험분석은 자산별로 깊게 분석하는 방식이며, 복합 접근법은 중요한 자산은 상세히 보고 나머지는 기준선으로 처리한다.

위험평가 이후에는 위험을 처리해야 한다. 위험수용은 비용이나 상황상 위험을 받아들이는 것이고, 위험감소는 통제를 적용해 가능성이나 영향을 낮추는 것이다. 위험회피는 위험이 있는 활동 자체를 중단하거나 우회하는 것이고, 위험전가는 보험이나 위탁처럼 책임·손실을 다른 주체로 이전하는 것이다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| 위험 구성 | 자산, 위협, 취약점, 가능성, 영향, 위험도 |
| 분석 방식 | 정량, 정성, 기준선, 상세, 복합, 델파이 |
| 계산 | SLE, ARO, ALE |
| 대응 | 수용, 감소, 회피, 전가 |
| 연속성 | BIA, BCP, DRP, RTO, RPO, hot/warm/cold/mirror |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | 위험대응 4전략, 위험분석 방법, SLE/ALE/ARO 용어 |
| 비교형 | 기준선/상세/복합, 정량/정성, RTO/RPO |
| 상황형 | 자산·위협·취약점 식별 후 대응전략 선택 |
| 서술형 | 위험관리 절차와 개인정보/ISMS-P 보호대책 연결 |

### 3단 답안
`위험관리는 자산에 대한 위협과 취약점을 식별하고 발생 가능성과 영향을 평가하는 과정이다. 위험을 평가하지 않으면 중요한 자산에 적절한 보호대책을 우선 적용하기 어렵다. 따라서 위험분석 결과에 따라 수용, 감소, 회피, 전가 중 적절한 전략을 선택하고 통제를 적용한다.`

### 암기 포인트
- 위험 = 자산 + 위협 + 취약점 + 영향
- 위험대응 = 수용, 감소, 회피, 전가
- ALE = SLE x ARO
- BIA는 업무 영향 분석, BCP/DRP는 업무연속성과 재해복구

## P1-2. 접근통제와 권한관리

### 왜 중요한가
접근통제는 정보보안 일반, 시스템 보안, 개인정보 보호, ISMS-P를 모두 연결한다. 하나의 과목에 갇힌 개념이 아니라 계정, 권한, 인증, 패스워드, PAM, 최소권한, 개인정보처리시스템 접근권한 관리까지 이어진다.

### 이해하기
접근통제는 사용자가 자원에 접근할 수 있는지 판단하고 제한하는 체계다. 식별은 사용자가 누구인지 주장하는 단계이고, 인증은 그 주장이 맞는지 확인하는 단계다. 인가는 인증된 사용자에게 어떤 권한을 줄지 결정하는 단계이며, 감사는 접근 기록을 남겨 사후 추적을 가능하게 한다.

DAC는 소유자가 접근권한을 부여하는 방식이다. MAC은 보안등급과 정책에 따라 강제적으로 접근을 통제한다. RBAC은 사용자의 역할에 따라 권한을 부여한다. 시험에서는 세 모델의 기준을 비교하거나, 개인정보처리시스템에서 권한 부여·변경·말소와 최소권한 원칙을 묻는 형태가 많다.

Linux에서는 PAM이 인증 흐름을 모듈화한다. `auth`는 인증, `account`는 계정 상태와 접근 가능성 확인, `password`는 패스워드 변경, `session`은 로그인 전후 세션 처리를 담당한다. 이 내용은 패스워드 정책, 계정 잠금, 접근권한 관리와 함께 외워야 한다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| 접근통제 절차 | 식별, 인증, 인가, 감사 |
| 접근통제 모델 | DAC, MAC, RBAC, BLP, Biba |
| 인증 | 지식, 소유, 존재, 행위, 위치, MFA |
| Linux 계정 | PAM auth/account/password/session, `/etc/passwd`, `/etc/shadow`, `login.defs` |
| 개인정보 권한관리 | 권한 부여·변경·말소, 최소권한, 계정 공유 금지, 기록 보관 |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | DAC/MAC/RBAC 기준, PAM 모듈명 |
| 설정형 | 패스워드 최소길이, 계정 잠금, 권한 말소 |
| 법규형 | 개인정보처리시스템 접근권한 관리 기준 |
| 비교형 | 인증/인가, DAC/MAC/RBAC, IAM/EAM |

### 3단 답안
`접근통제는 인증된 사용자가 허가된 자원에만 접근하도록 제한하는 보안 통제다. 권한이 과도하거나 계정 관리가 부실하면 개인정보 유출과 내부자 오남용이 발생할 수 있다. 따라서 최소권한 원칙에 따라 권한을 부여·변경·말소하고, 인증 정책과 접근기록 점검을 함께 운영한다.`

### 암기 포인트
- DAC = 소유자 재량
- MAC = 등급·정책 강제
- RBAC = 역할 기반
- PAM = auth, account, password, session

## P1-3. Linux/Unix 로그·명령·권한

### 왜 중요한가
최근 23~30회에서 시스템 보안 비중이 상승했고, Linux/Unix 로그·명령은 최근성이 특히 강하다. 단답형으로 파일명이나 명령어를 묻기도 하고, 실무형으로 로그나 설정을 보고 보안 의미를 묻기도 한다.

### 이해하기
Linux 계정 보안은 `/etc/passwd`와 `/etc/shadow`에서 시작한다. `/etc/passwd`는 계정 기본정보를 담고, `/etc/shadow`는 패스워드 해시와 만료 정보를 보호한다. shadow 파일의 해시 식별자는 알고리즘을 구분하는 단서가 된다. `$1$`은 MD5, `$5$`는 SHA-256, `$6$`은 SHA-512로 정리한다.

로그 파일은 침해사고 판단근거다. `utmp`는 현재 로그인 세션, `wtmp`는 로그인/로그아웃 이력, `btmp`는 로그인 실패 기록, `lastlog`는 마지막 로그인 정보를 다룬다. `last`, `lastb`, `lastlog`, `lastcomm`, `lsof` 같은 명령은 로그와 프로세스 상태를 확인하는 도구다.

권한에서는 SUID, SGID, sticky bit가 반복된다. SUID는 실행 시 파일 소유자 권한으로 실행되게 하고, SGID는 그룹 권한으로 실행되게 한다. sticky bit는 공용 디렉터리에서 자기 파일이 아닌 파일 삭제를 제한하는 데 쓰인다. 권한 문제는 `chmod`, `find -perm`, world-writable, umask와 함께 나온다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| 계정 파일 | `/etc/passwd`, `/etc/shadow`, `login.defs`, `securetty` |
| 로그 | `utmp`, `wtmp`, `btmp`, `lastlog`, `/var/log/messages` |
| 명령 | `last`, `lastb`, `lastlog`, `lastcomm`, `lsof`, `find`, `chmod`, `chattr` |
| 권한 | SUID, SGID, sticky bit, umask, world-writable |
| 서비스 제어 | xinetd, `only_from`, `no_access`, `instances`, `access_time`, iptables |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | 로그인 실패 파일, 열린 파일 확인 명령, shadow 해시 식별자 |
| 설정형 | xinetd 접근제어, iptables 정책, 패스워드 정책 |
| 로그형 | 인증 실패, 비정상 로그인, 실행 명령 추적 |
| 취약점형 | SUID 오남용, world-writable 파일, root 직접 로그인 |

### 3단 답안
`Linux 로그와 명령은 계정 사용, 로그인 실패, 프로세스 실행, 파일 접근 상태를 확인하는 운영체제 점검 수단이다. 침해사고나 권한 오남용은 로그와 파일 권한에 흔적을 남기므로 이를 모르면 판단근거를 제시하기 어렵다. 따라서 로그인 기록은 utmp/wtmp/btmp/lastlog와 last 계열 명령으로 확인하고, 권한은 chmod/find/umask 및 특수비트를 점검해 보완한다.`

### 암기 포인트
- 로그인 실패 = `btmp`, `lastb`
- 열린 파일/프로세스 = `lsof`
- 실행 명령 이력 = `lastcomm`
- 특수권한 = SUID, SGID, sticky

## P1-4. 서비스 보안설정

### 왜 중요한가
최근 23~30회 KCA 세부항목에서 서비스 보안설정 점검과 보완이 가장 많이 연결된다. 서비스 설정은 웹, DNS, SNMP, NTP, SMTP, DB, Apache/IIS로 넓게 퍼지지만 답안 구조는 같다. “어떤 설정이 위험한가, 왜 위험한가, 어떻게 제한하는가”를 쓰면 된다.

### 이해하기
서비스 보안설정은 불필요한 기능을 끄고, 접근 대상을 제한하고, 인증·권한·로그를 강화하는 작업이다. Apache에서 디렉터리 리스팅이 가능하면 파일 목록이 노출될 수 있으므로 `Options Indexes`를 제거하거나 `-Indexes`로 제한한다. TRACE 메서드는 XST 등과 연결될 수 있어 `TraceEnable Off`처럼 비활성화한다.

DNS에서는 zone transfer가 핵심이다. master/slave 구조에서 zone transfer가 외부에 열려 있으면 내부 도메인 구조와 호스트 정보가 노출될 수 있다. 따라서 `allow-transfer`를 slave DNS 등 필요한 IP로 제한해야 한다.

SNMP는 community string, 버전, 접근제어가 중요하다. 기본 community를 사용하거나 쓰기 권한을 열어두면 장비 정보 노출과 설정 변경 위험이 있다. SNMPv3, ACL 제한, read-only 권한을 함께 기억한다. NTP는 monlist 기능이 증폭 공격에 악용될 수 있으므로 버전 업그레이드, `disable monitor`, ACL, rate limit를 연결한다.

SMTP는 open relay 차단이 핵심이다. 메일 서버가 누구에게나 릴레이를 허용하면 스팸 발송지로 악용된다. DB는 최소권한, 감사 설정, 로그 외부 보관이 중요하다. 감사 로그가 DB 내부에만 있으면 관리자나 공격자에 의해 변조될 수 있으므로 별도 로그 서버나 무결성 보호가 필요하다.

### 같이 묶어 외울 것
| 서비스 | 핵심 위험 | 대응 키워드 |
|---|---|---|
| Apache/IIS | 디렉터리 리스팅, TRACE, 불필요 메서드 | `-Indexes`, `TraceEnable Off`, 접근제어 |
| DNS | zone transfer, cache poisoning, DRDoS | `allow-transfer`, recursion 제한, rate limit |
| SNMP | community 노출, 쓰기 권한 | SNMPv3, ACL, read-only, community 변경 |
| NTP | monlist 증폭 | `disable monitor`, 업그레이드, ACL |
| SMTP | open relay | relay 제한, 인증, access DB |
| DB | 과도한 권한, 감사로그 변조 | 최소권한, audit, 외부 로그 보관 |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 설정형 | 지시자 의미와 권장 설정 |
| 취약점형 | 설정이 열려 있을 때 발생하는 위험 |
| 대응형 | 접근제어, 버전 업그레이드, 로그 보관, 최소권한 |
| 실무형 | 설정 파일 일부를 보고 보안상 문제 찾기 |

### 3단 답안
`서비스 보안설정은 웹, DNS, SNMP, NTP, SMTP, DB 같은 서비스의 불필요 기능과 접근 범위를 제한하는 보안 조치다. 기본 설정이나 공개 설정이 남아 있으면 정보 노출, 권한 오남용, 증폭 공격, 불법 릴레이로 이어질 수 있다. 따라서 접근 가능한 IP와 권한을 제한하고, 위험한 기능을 비활성화하며, 로그와 감사 설정을 별도로 보관·점검한다.`

### 암기 포인트
- Apache = `Options -Indexes`, `TraceEnable Off`
- DNS = `allow-transfer` 제한
- SNMP = SNMPv3, ACL, read-only
- NTP = `disable monitor`
- DB = 최소권한, 감사, 외부 로그

## P2-1. 웹 취약점과 시큐어코딩

### 왜 중요한가
웹 취약점은 단답형과 실무형을 모두 오간다. SQL Injection, XSS, SSRF, XXE, 파일 업로드, CRLF, HTTP request smuggling은 이름만 외우면 부족하고 입력값, 영향, 대응을 함께 써야 한다.

### 이해하기
웹 취약점의 공통 원인은 신뢰할 수 없는 입력을 검증하지 않고 해석하는 것이다. SQL Injection은 입력값이 SQL 구조를 바꾸는 취약점이다. PreparedStatement는 SQL 구조와 파라미터를 분리해 입력값이 쿼리 문법으로 실행되지 않게 한다.

XSS는 사용자 입력이 브라우저에서 스크립트로 실행되는 취약점이다. Stored XSS는 서버에 저장된 악성 스크립트가 실행되고, Reflected XSS는 요청에 포함된 값이 응답에 반사되어 실행된다. DOM XSS는 클라이언트 스크립트가 DOM을 조작하는 과정에서 발생한다. 대응은 입력검증만으로 끝나지 않고 출력 인코딩, CSP, 쿠키의 HttpOnly/Secure 속성과 함께 봐야 한다.

SSRF는 서버가 사용자 입력 URL을 기반으로 내부망이나 외부 자원에 요청을 보내는 취약점이다. 공격자는 서버를 대리 요청자로 사용해 내부 IP, metadata endpoint, 관리자 서비스에 접근할 수 있다. 대응은 allowlist, 내부 IP 차단, URL 검증, 리다이렉트 제한이다.

파일 업로드 취약점은 업로드된 파일이 서버에서 실행될 때 위험해진다. 확장자나 MIME만 신뢰하면 우회될 수 있으므로 저장 경로, 실행권한, 난수 파일명, 웹루트 외부 저장, 콘텐츠 검사까지 연결한다.

### 같이 묶어 외울 것
| 취약점 | 원리 | 대응 |
|---|---|---|
| SQL Injection | 입력값이 SQL 구조 변조 | PreparedStatement, 입력검증, 오류 제한, 최소권한 |
| XSS | 스크립트가 브라우저에서 실행 | 출력 인코딩, CSP, HttpOnly, 입력검증 |
| SSRF | 서버가 내부/외부 URL 요청 | allowlist, 내부 IP 차단, URL 검증 |
| XXE | XML 외부 엔티티 처리 악용 | 외부 엔티티 비활성화, parser 보안 설정 |
| 파일 업로드 | 업로드 파일 실행 | 확장자/MIME/내용 검증, 실행권한 제거, 웹루트 외부 저장 |
| CRLF/응답분할 | CR/LF로 헤더 경계 조작 | 개행문자 필터링, 헤더 API 사용 |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | 공격명, CR/LF, XSS 유형, PreparedStatement |
| 코드형 | 취약한 입력 처리 코드의 문제점 |
| 로그형 | URL 파라미터나 HTTP 요청에서 공격 식별 |
| 서술형 | 원리, 영향, 대응방안 2~3개 |

### 3단 답안
`SQL Injection은 사용자 입력이 SQL 문법으로 해석되어 쿼리 구조를 변조하는 웹 취약점이다. 인증 우회, 데이터 조회·변조·삭제로 이어질 수 있어 DB 기밀성과 무결성에 직접 영향을 준다. 따라서 PreparedStatement로 쿼리와 파라미터를 분리하고, 입력검증, DB 최소권한, 오류 메시지 제한을 적용한다.`

### 암기 포인트
- SQLi = PreparedStatement
- XSS = 출력 인코딩 + CSP + HttpOnly
- SSRF = allowlist + 내부 IP 차단
- 파일 업로드 = 웹루트 외부 저장 + 실행권한 제거
- CR/LF = `%0D`, `%0A`

## P2-2. DNS/SNMP/VLAN과 네트워크 장비

### 왜 중요한가
네트워크 보안은 전체 비중이 크고, 최근에도 DNS/SNMP/VLAN/장비 설정이 반복된다. 단순 프로토콜 암기보다 “동작 원리, 공격 방식, 설정 대응”을 연결해야 점수가 나온다.

### 이해하기
DNS는 이름을 IP 주소로 변환하는 서비스다. UDP/TCP 53을 사용하며, cache와 TTL을 통해 반복 질의 부담을 줄인다. 보안상 중요한 문제는 zone transfer, cache poisoning, open resolver, DNS amplification이다. zone transfer는 내부 도메인 정보를 외부에 노출할 수 있고, open resolver는 증폭 공격에 악용될 수 있다.

SNMP는 네트워크 장비를 관리하는 프로토콜이다. manager, agent, MIB 구조를 기억한다. 기본 community string이나 쓰기 권한이 노출되면 장비 정보가 유출되거나 설정 변경 위험이 생긴다.

VLAN은 물리적으로 같은 스위치에 연결된 장비를 논리적으로 분리하는 기술이다. 브로드캐스트 도메인을 분리하고 네트워크 접근 범위를 줄이는 데 쓰인다. 포트 기반 VLAN은 포트에 VLAN을 할당하고, MAC 기반 VLAN은 MAC 주소에 따라, 프로토콜 기반 VLAN은 프로토콜에 따라 분리한다.

라우터와 스위치 보안에서는 ACL, ingress/egress filtering, uRPF, source routing 차단, 불필요한 ICMP 제한, SNMP 제한 같은 운영 설정이 중요하다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| DNS | UDP/TCP 53, cache, TTL, zone transfer, recursion, DRDoS |
| SNMP | manager, agent, MIB, 161/162, community, SNMPv3 |
| VLAN | 포트 기반, MAC 기반, 프로토콜 기반, 브로드캐스트 도메인 |
| 장비 설정 | ACL, ingress, egress, uRPF, source route 차단 |
| 공격 | ARP spoofing, SYN flood, Smurf, DRDoS, scan/sniffing |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | DNS 포트, SNMP 구성요소, VLAN 종류 |
| 설정형 | zone transfer 제한, SNMP ACL, 라우터 필터링 |
| 공격형 | DRDoS, ARP spoofing, Smurf, scan |
| 비교형 | 포트/MAC/프로토콜 기반 VLAN |

### 3단 답안
`VLAN은 하나의 물리 네트워크를 여러 논리 네트워크로 분리하는 기술이다. 네트워크를 분리하지 않으면 브로드캐스트 범위와 접근 가능 범위가 커져 내부 이동과 정보 노출 위험이 증가한다. 따라서 포트, MAC, 프로토콜 기준으로 VLAN을 구성하고 ACL과 장비 보안설정을 함께 적용해 접근 범위를 제한한다.`

### 암기 포인트
- DNS = 53, zone transfer, recursion 제한
- SNMP = manager/agent/MIB, 161/162, SNMPv3
- VLAN = 포트/MAC/프로토콜 기반
- DRDoS = 출발지 위조 + 반사/증폭 + uRPF/BCP38

## P2-3. 개인정보, ISMS-P, 법규

### 왜 중요한가
관리 및 법규는 전체 1~30회에서 가장 큰 과목 비중을 차지한다. 법규는 세부 조문 암기보다 개인정보 처리 상황에서 어떤 보호조치가 필요한지 쓰는 문제가 많다. 위험관리, 접근통제, 로그, 암호화와 함께 공부해야 한다.

### 이해하기
개인정보 보호의 핵심은 개인정보 처리 단계마다 필요한 안전조치를 적용하는 것이다. 접근권한 관리는 개인정보처리시스템에 누가 접근할 수 있는지를 통제한다. 권한 부여·변경·말소 절차, 최소권한, 계정 공유 금지, 권한 기록 보관을 함께 봐야 한다.

접속기록 관리는 누가 언제 어디서 어떤 개인정보 처리 업무를 수행했는지 추적하기 위한 조치다. 시험 답안에서는 계정 또는 접속자 식별정보, 접속일시, 접속지 정보, 처리한 정보주체 정보, 수행업무 또는 처리내역을 묶어 쓴다. 세부 보관기간과 점검주기는 최신 법령·고시 기준 확인이 필요하므로, 이 통합본에서는 항목과 목적 중심으로 학습한다. 암호화는 저장·전송되는 개인정보가 유출되어도 내용을 바로 알 수 없게 하는 보호조치다.

ISMS-P는 관리체계 수립·운영, 보호대책 요구사항, 개인정보 처리단계별 요구사항으로 이해한다. 시험에서는 영역명을 묻거나, 특정 상황에서 어떤 통제가 필요한지 묻는다. 법규 문제는 최신성이 중요하므로 세부 숫자는 최신 원천 확인이 필요하지만, 시험 답안은 주체·의무·기록·보관·통지·점검 중심으로 구성한다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| 접근권한 | 부여, 변경, 말소, 최소권한, 계정 공유 금지 |
| 접속기록 | 계정/접속자, 일시, 접속지, 정보주체, 수행업무, 점검, 보관 |
| 암호화 | 저장, 전송, 비밀번호, 고유식별정보 |
| ISMS-P | 관리체계, 보호대책, 개인정보 처리단계 |
| 법규 상황 | 유출 통지·신고, 위탁, CISO, 영상정보처리기기 |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | ISMS-P 영역, 안전성 확보조치 키워드 |
| 상황형 | 유출, 위탁, CCTV, 접근권한 문제 |
| 서술형 | 접속기록 관리 목적과 기록 항목 |
| 비교형 | 관리적/기술적/물리적 보호조치 |

### 3단 답안
`개인정보처리시스템 접근권한 관리는 개인정보에 접근할 수 있는 사용자의 권한을 부여·변경·말소하고 통제하는 보호조치다. 권한이 과도하거나 퇴직자 계정이 남아 있으면 개인정보 유출과 오남용 위험이 커진다. 따라서 최소권한 원칙에 따라 권한을 관리하고, 권한 변경 이력과 접속기록을 보관·점검한다.`

### 암기 포인트
- ISMS-P = 관리체계 + 보호대책 + 개인정보 처리단계
- 개인정보 = 접근권한, 접속기록, 암호화, 접근통제
- 법규 답안 = 주체 + 의무 + 기록/보관 + 통지/점검

## P2-4. IDS/IPS, Snort, 관제

### 왜 중요한가
관제와 탐지는 단답, 로그형, 실무형으로 반복된다. Snort 룰, IDS/IPS 차이, HIDS/NIDS 차이, FP/FN은 짧게 묻기도 하고 로그분석·대응 문제로 확장되기도 한다.

### 이해하기
IDS는 침입을 탐지하는 시스템이고, IPS는 탐지 후 차단까지 수행하는 시스템이다. HIDS는 호스트 내부의 로그, 파일, 프로세스, 무결성을 감시하고, NIDS는 네트워크 구간의 패킷과 트래픽을 감시한다.

탐지 결과에서는 false positive와 false negative를 구분해야 한다. false positive는 정상인데 공격으로 탐지한 오탐이고, false negative는 공격인데 탐지하지 못한 미탐이다. 시험에서는 관제 정확도나 탐지 정책의 한계를 묻는 식으로 나온다.

Snort 룰은 header와 option으로 본다. header에는 action, protocol, source/destination IP와 port, direction이 들어가고, option에는 `msg`, `content`, `sid`, `rev`, `nocase`, `threshold` 또는 `detection_filter` 같은 조건이 들어간다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| 탐지 장비 | IDS, IPS, HIDS, NIDS |
| 탐지 품질 | false positive, false negative |
| Snort header | action, protocol, IP, port, direction |
| Snort option | msg, content, sid, rev, nocase, threshold |
| 관제 | SIEM, SOAR, ESM, 로그 수집, 상관분석 |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | IDS/IPS, HIDS/NIDS, FP/FN |
| 룰 해석형 | Snort option 의미 |
| 로그형 | 탐지 이벤트를 보고 공격·대응 식별 |
| 서술형 | 관제 구성요소와 대응 절차 |

### 3단 답안
`Snort는 네트워크 패킷을 룰 기반으로 분석해 침입을 탐지하는 IDS 도구다. 룰 조건을 정확히 이해하지 못하면 정상 트래픽을 오탐하거나 실제 공격을 미탐할 수 있다. 따라서 header에서 탐지 대상 트래픽을 지정하고 option에서 content, msg, sid, threshold 같은 세부 조건을 설정해 탐지 정확도를 조정한다.`

### 암기 포인트
- IDS = 탐지, IPS = 탐지+차단
- HIDS = 호스트, NIDS = 네트워크
- FP = 정상인데 공격, FN = 공격인데 정상
- Snort = header + options

## P3-1. IPSec, TLS, 암호통신

### 왜 중요한가
IPSec과 TLS는 빈도는 P1/P2보다 낮지만 반복성이 있고, 네트워크 보안·암호·서비스 보안이 연결되는 주제다. 구성요소를 정확히 외우면 단답형 점수를 확보하기 좋다.

### 이해하기
IPSec은 IP 계층에서 패킷을 보호하는 보안 프로토콜 묶음이다. AH는 인증과 무결성을 제공하고, ESP는 기밀성, 인증, 무결성을 제공한다. IKE는 보안연관과 키 교환을 담당한다. 전송 모드는 IP payload를 중심으로 보호하고, 터널 모드는 원래 IP 패킷 전체를 새 IP 패킷 안에 넣어 보호한다.

TLS는 전송 계층 위에서 응용 데이터의 기밀성, 무결성, 인증을 제공한다. 시험에서는 TLS handshake 세부를 깊게 묻기보다 SSL/TLS 취약점, 인증서, E2EE, 인증서 고정, 취약 프로토콜 비활성화와 함께 나올 가능성이 높다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| IPSec | AH, ESP, IKE, SA, transport, tunnel |
| 보안 기능 | 기밀성, 무결성, 인증, 재생공격 방지 |
| TLS | 인증서, handshake, 암호스위트, MITM |
| 취약점 | HeartBleed, POODLE, FREAK, LogJam, DROWN |
| 모바일 연결 | E2EE, certificate pinning |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | AH/ESP/IKE 기능 |
| 비교형 | 전송 모드/터널 모드, AH/ESP |
| 취약점형 | SSL/TLS 취약점 이름과 영향 |
| 상황형 | MITM 대응, 인증서 고정, E2EE |

### 3단 답안
`IPSec은 IP 계층에서 패킷의 인증, 무결성, 기밀성을 제공하는 보안 프로토콜 체계다. 네트워크 구간에서 패킷이 도청·변조·재전송될 수 있으므로 통신 보호가 필요하다. 따라서 AH로 인증·무결성을 제공하고, ESP로 기밀성을 포함한 보호를 수행하며, IKE로 키 교환과 보안연관을 설정한다.`

### 암기 포인트
- AH = 인증·무결성
- ESP = 기밀성 + 인증·무결성
- IKE = 키 교환
- tunnel = 원 IP 패킷 전체 보호

## P3-2. DB 보안과 데이터보호

### 왜 중요한가
DB와 데이터보호는 단독 빈도는 중간이지만 웹 취약점, 개인정보, 서비스 설정과 자주 연결된다. SQL Injection, 개인정보 암호화, DB 감사, DLP, 마스킹은 따로 외우지 말고 데이터 보호 흐름으로 묶어야 한다.

### 이해하기
DB 보안의 핵심은 권한, 감사, 암호화다. 권한은 최소권한 원칙에 따라 필요한 작업만 허용해야 한다. `GRANT`는 권한 부여, `REVOKE`는 권한 회수다. 감사는 누가 어떤 데이터에 접근하고 변경했는지 추적하는 기능이다. 감사 로그는 내부에만 두면 변조될 수 있으므로 외부 보관이나 무결성 보호가 필요하다.

DB 암호화는 API 방식, Plug-in 방식, TDE 같은 방식으로 설명될 수 있다. 시험에서는 구현 내부보다 저장 데이터 보호 목적과 운영상 장단점을 묻는 쪽에 대비한다. DLP는 data in use, data in motion, data at rest 상태의 데이터 유출을 탐지·차단하는 체계로 정리한다.

마스킹은 개인정보 일부를 가려 테스트나 조회 환경에서 노출을 줄이는 기술이다. 다만 세부 방식명은 직접 원천 보강 전까지 과도하게 확신하지 않고, 개인정보 보호조치와 DB 데이터 노출 최소화 관점으로 보수적으로 학습한다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| DB 권한 | GRANT, REVOKE, 최소권한, view |
| DB 감사 | audit, 감사로그, 외부 보관, 무결성 |
| DB 암호화 | API, Plug-in, TDE |
| 데이터보호 | DLP, masking, encryption, access control |
| 데이터 상태 | in use, in motion, at rest |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | SQL 분류, DLP 보호 상태, GRANT/REVOKE |
| 설정형 | DB 감사 설정, 외부 로그 보관 |
| 개인정보형 | 암호화, 마스킹, 접근권한 |
| 서술형 | 감사 로그 변조 위험과 개선방안 |

### 3단 답안
`DB 감사는 데이터베이스에서 수행된 접속, 조회, 변경, 권한 사용 내역을 기록하는 보안 기능이다. 감사 로그가 없거나 내부에만 저장되면 권한 오남용과 개인정보 유출을 추적하기 어렵고 로그 변조 위험도 커진다. 따라서 감사 기능을 활성화하고, 중요 감사 로그는 외부 로그 서버에 보관하며 접근통제와 무결성 점검을 적용한다.`

### 암기 포인트
- DB = 권한 + 감사 + 암호화
- DLP = in use, in motion, at rest
- 감사로그 = 외부 보관 + 무결성
- 마스킹 = 개인정보 노출 최소화

## P3-3. 악성코드, APT, 포렌식

### 왜 중요한가
악성코드/APT/포렌식은 최근성 신호가 있다. 다만 세부 프레임워크 이름을 깊게 외우기보다 침해사고를 어떻게 단계적으로 보고, 증거를 어떻게 보존하고, 어떤 로그와 도구를 보는지 이해하는 것이 중요하다.

### 이해하기
APT는 장기간 은닉하며 목표 조직을 단계적으로 침투하는 공격이다. 정찰, 침투, 명령제어, 내부 이동, 목표 달성 같은 흐름으로 이해하면 된다. Cyber Kill Chain은 medium confidence 항목이 있으므로 전용 공식 원천 보강 전까지는 단계 모델을 과도하게 단정하지 않고, APT 분석 관점의 보조 개념으로 둔다. MITRE ATT&CK은 공격 전술과 기술을 정리한 지식베이스로 이해한다.

포렌식은 증거를 수집, 보존, 분석, 보고하는 절차다. 무결성, 정당성, 연계보관성, 재현성 같은 원칙이 중요하다. 침해사고에서는 휘발성 데이터부터 수집하고, 로그와 파일 무결성, 프로세스, 네트워크 연결, 계정 흔적을 함께 본다.

악성코드 분석에서는 PE 파일, 웹셸, 루트킷, 제로데이, 공급망 공격 같은 키워드가 나온다. 시험에서는 깊은 리버싱보다 공격 식별, 영향, 대응방안을 쓰는 방식에 대비한다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| APT | 정찰, 침투, C2, 내부 이동, 목표 달성 |
| 분석 체계 | Kill Chain, MITRE ATT&CK |
| 포렌식 | 증거 수집, 보존, 분석, 보고, 무결성, chain of custody |
| 침해 흔적 | 로그, 프로세스, 네트워크 연결, 계정, 파일 무결성 |
| 악성코드 | PE, 웹셸, 루트킷, 제로데이, 공급망 공격 |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | 포렌식 원칙, 제로데이, 웹셸 |
| 상황형 | 로그나 파일 흔적을 보고 침해 판단 |
| 서술형 | APT 단계와 탐지·대응 |
| 도구형 | Tripwire, chkrootkit, Nessus, Nikto |

### 3단 답안
`디지털 포렌식은 침해사고와 관련된 디지털 증거를 수집·보존·분석·보고하는 절차다. 증거가 훼손되거나 수집 과정이 불명확하면 사고 원인 규명과 법적 증거 활용이 어려워진다. 따라서 휘발성 데이터 우선 수집, 무결성 해시 확보, 연계보관성 유지, 분석 결과 문서화를 수행한다.`

### 암기 포인트
- 포렌식 = 수집, 보존, 분석, 보고
- 증거 = 무결성 + 연계보관성
- APT = 단계적 침투 + 장기 은닉
- 도구 = Tripwire, chkrootkit, Nessus, Nikto

## P3-4. 무선, 모바일, 저빈도 보강

### 왜 중요한가
무선/모바일은 전체 빈도는 낮지만 최근 확장 신호가 있다. 깊게 파기보다 단답형과 상황형에 대응할 정도로 정리한다.

### 이해하기
무선 보안은 WEP, WPA, WPA2, WPA3 같은 표준과 CSMA/CA, RTS/CTS 같은 매체 접근 개념이 나온다. 세부 표준은 직접 원천 보강 대상이므로 큰 흐름 위주로 본다.

모바일 보안은 MDM, MAM, MCM, EMM, BYOD, deep link, 인증서 고정 같은 키워드가 나온다. MDM은 단말 관리, MAM은 애플리케이션 관리, MCM은 콘텐츠 관리, EMM은 기업 모바일 관리를 포괄하는 개념으로 정리한다. deep link는 앱의 특정 화면이나 기능으로 직접 이동시키는 링크이며, 인증·인가 검증이 없으면 민감 기능 호출 위험이 생긴다.

### 같이 묶어 외울 것
| 묶음 | 같이 외울 키워드 |
|---|---|
| 무선 | WEP, WPA/WPA2/WPA3, CSMA/CA, RTS/CTS |
| 모바일 관리 | MDM, MAM, MCM, EMM, BYOD |
| 모바일 앱 | deep link, 인증/인가, URL scheme, certificate pinning |
| 보수 학습 | 세부 표준명은 시험 전날 용어 수준 확인 |

### 시험에서 나오는 방식
| 유형 | 출제 방식 |
|---|---|
| 단답형 | MDM/MAM/MCM/EMM, deep link |
| 비교형 | 무선 보안 표준, 모바일 관리 기술 |
| 상황형 | deep link 인증 우회, BYOD 보안 |

### 3단 답안
`Deep link는 모바일 앱의 특정 화면이나 기능으로 직접 이동하게 하는 연결 방식이다. 인증과 인가 검증 없이 민감 기능을 호출하면 권한 없는 사용자가 내부 기능에 접근할 수 있다. 따라서 deep link 진입 시 사용자 인증과 권한을 재검증하고, URL scheme과 파라미터를 검증하며 민감 기능은 재인증을 요구한다.`

### 암기 포인트
- MDM = 단말 관리
- MAM = 앱 관리
- MCM = 콘텐츠 관리
- EMM = 기업 모바일 관리
- deep link = 직접 이동 + 인증/인가 검증

### 설정·프로토콜
| 항목 | 키워드 |
|---|---|

### 공격·대응

## 후순위·제거 목록
| 항목 | 처리 | 이유 |
|---|---|---|
| 무선랜 세부 표준의 깊은 차이 | 용어 수준 확인 | medium 항목이며 세부 표준 원천 보강 전까지 과투자 금지 |
| Cyber Kill Chain 세부 단계 암기 | APT 분석 흐름 수준 확인 | 전용 공식 원천 보강 전까지 보수적으로 학습 |
| DB 마스킹 방식명 세부 분류 | 개인정보 보호조치 관점으로 학습 | 방식명 직접 원천이 부족해 과도한 확신 금지 |
| EAM/IAM 벤더별 차이 | 접근권한 관리 관점으로 학습 | 벤더 용어 차이가 있어 시험 답안에서는 보수 표현 |
| CVE별 세부 취약 버전 | 주요 영향과 대응 중심 | 깊은 버전 암기보다 취약점 관리 절차가 효율적 |

## 합격 가능성 판단
이 통합본은 60점 이상을 보장하는 문서가 아니라, 3주 안에 합격 가능성을 높이기 위해 학습 범위를 압축한 기준선이다. 기출과 예상문제를 함께 풀면서 아래 조건을 만족하면 60점 이상을 현실적인 목표로 볼 수 있다.

| 조건 | 합격 가능성에 미치는 영향 |
|---|---|
| P1 단원 80% 이상을 단답과 3단 답안으로 쓸 수 있다. | 합격선의 핵심이다. 위험관리, 접근통제, Linux/Unix, 서비스 설정에서 기본 점수를 확보한다. |
| P2 단원 70% 이상을 공격명·판단근거·대응방안으로 연결할 수 있다. | 고득점과 변형문제 대응의 중심이다. 웹, 네트워크, 개인정보, 관제에서 부분점수를 만든다. |
| 최근 23~30회 기출을 최소 1회전 이상 풀고 오답을 이 문서의 단원으로 되돌려 정리한다. | 문서 이해가 실제 문제 풀이로 전환되는지 확인한다. |
| 예상문제 36문항을 시간 제한 안에서 2회 이상 작성한다. | 알고 있는 내용을 시험장 문장으로 쓰는 훈련이다. |
| 법규 세부 숫자·기간·고시 변경 가능 항목은 시험 직전에 최신 자료로 확인한다. | 법규 최신성 리스크를 줄인다. |

반대로 P1을 읽기만 하고 직접 쓰지 못하거나, 기출을 풀었을 때 단답형 키워드가 계속 빠지면 60점 이상은 어렵다. 이 경우 P3를 줄이고 P1/P2 오답 회수에 시간을 다시 배정한다.
