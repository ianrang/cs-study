# 1 시스템 보안

> 목표: 운영체제의 인증·권한·로그·보안설정을 보고 **취약점, 위험, 보완 방법**을 답안으로 쓴다. 이 문서는 KCA 실기 출제기준의 `운영체제별 보안특성 파악`과 `운영체제 보안설정 점검과 보완` 범위를 시험용으로 정리한다.

## 1.1 [P1] Linux 계정·인증·권한

### 1.1.1 [P1] 계정 파일과 필드

- `/etc/passwd`: 계정 기본 정보. 일반적으로 두 번째 필드가 `x`이면 실제 패스워드 해시는 `/etc/shadow`에 있다.
  - 형식: `계정명:x:UID:GID:GECOS:홈디렉터리:로그인셸`
- `/etc/shadow`: 패스워드 해시와 만료 정책을 보호한다.
  - 형식: `계정명:해시:최종변경일:최소일:최대일:경고일:비활성일:만료일:예약필드`
  - 해시 식별자 예: `$1$` MD5, `$5$` SHA-256, `$6$` SHA-512. 식별자는 알고리즘 단서이며, 실제 해시는 salt와 해시값을 함께 포함한다.
  - 패스워드 필드 앞의 `!`는 패스워드 기반 로그인을 잠그는 데 사용된다. 기호의 정확한 조합은 배포판·계정 생성 방식에 따라 달라질 수 있으므로, 시험에서는 **잠금 여부와 보안 목적**을 우선 판단한다.
- `/etc/group`: 그룹명·GID·보조 그룹 구성원을 관리한다.

**[답안]** `shadow`는 패스워드 해시와 만료 정보를 일반 사용자에게 노출하지 않도록 보호한다. 권한이 느슨하면 해시 탈취 후 오프라인 크래킹 위험이 커지므로 root만 읽을 수 있게 제한한다.

### 1.1.2 [P1] PAM과 패스워드 정책

- PAM(Pluggable Authentication Modules)은 인증 정책을 모듈화한다.
  - `auth`: 사용자의 인증 정보 검증
  - `account`: 계정 유효성·접근 가능 시간·잠금 등 계정 상태 확인
  - `password`: 패스워드 변경 정책 처리
  - `session`: 로그인 전후 세션 작업 처리
- 패스워드 정책의 핵심은 길이·문자 종류·사전어·재사용 제한·사용 기간·실패 잠금·세션 타임아웃이다.
- `pam_pwquality`와 `/etc/security/pwquality.conf`는 대표적인 품질 점검 조합이다. 예를 들어 `minlen`, `minclass`, `retry`는 각각 최소 길이, 문자 종류, 재시도 횟수와 연결한다.
- 실패 잠금은 `pam_faillock`의 `deny`, `unlock_time` 같은 정책으로 구현할 수 있다. 실제 PAM 파일 경로와 모듈 구성은 배포판·버전에 따라 다르므로, **문제에서 제시한 파일·모듈·값을 우선**한다.
- 세션 타임아웃 예: `/etc/profile` 등에 `TMOUT`을 설정하여 유휴 세션 노출을 줄인다.

**[답안]** 패스워드 정책은 추측·재사용·무차별 대입으로 인한 계정 탈취를 줄이기 위한 통제다. 길이·복잡도·만료·실패 잠금·유휴 세션 종료를 적용하고, 계정 부여·변경·삭제 이력을 관리한다.

### 1.1.3 [P1] 파일 권한과 특수권한

- 일반 권한: 소유자(user), 그룹(group), 기타(other)에 대해 읽기·쓰기·실행 권한을 설정한다.
- SUID: 실행 파일이 실행 시 **파일 소유자**의 유효 권한으로 동작한다. 불필요한 SUID는 권한 상승 위험이 있다.
- SGID: 실행 파일은 파일 그룹의 유효 권한으로 동작할 수 있고, 디렉터리에서는 새 파일이 디렉터리 그룹을 상속한다.
- Sticky bit: 공용 쓰기 디렉터리에서 파일 소유자·디렉터리 소유자·root 외의 삭제/이름 변경을 제한한다.
- 자주 나오는 점검 명령:

```bash
# SUID가 설정된 일반 파일 찾기
find / -type f -perm -4000

# SGID가 설정된 일반 파일 찾기
find / -type f -perm -2000

# other 쓰기 권한이 있는 일반 파일 찾기
find / -type f -perm -0002

# 소유자 또는 그룹이 없는 파일 찾기
find / \( -nouser -o -nogroup \)
```

- 대표 점검 예: `/etc/passwd`는 일반적으로 `644`, `/etc/shadow`는 일반적으로 `400` 또는 더 제한된 권한을 사용한다. 정확한 기준값은 문제의 운영체제·점검 기준을 따른다.
- 권한 변경·기본 권한 계산도 함께 연결한다.

```bash
# 권한 변경: 소유자 rw, 그룹 r, 기타 r
chmod 644 파일명

# 소유자와 그룹 변경
chown 사용자:그룹 파일명

# 새 파일·디렉터리의 기본 권한 마스크 설정 예
umask 022
```

- `umask`는 허용 권한이 아니라 새 객체의 기본 권한에서 제거할 권한 비트다. 일반적으로 파일은 `666`, 디렉터리는 `777`에서 umask를 적용한다. 예를 들어 `umask 022`이면 일반 파일은 보통 `644`, 디렉터리는 `755`가 된다.

### 1.1.4 [P1] 로그인·감사 로그와 명령

| 기록/명령 | 의미 | 시험 포인트 |
|---|---|---|
| `utmp`, `who`, `w` | 현재 로그인 세션 | 현재 접속자 확인 |
| `wtmp`, `last` | 로그인·로그아웃·재부팅 이력 | 과거 접속 이력 확인 |
| `btmp`, `lastb` | 로그인 실패 이력 | 무차별 대입·비정상 로그인 탐지 |
| `lastlog`, `lastlog` | 계정별 마지막 로그인 정보 | 장기간 미사용·의심 계정 점검 |
| `lastcomm` | process accounting이 켜진 환경의 실행 명령 이력 | 사용자가 실행한 명령 추적 |
| `lsof` | 열린 파일과 이를 사용하는 프로세스 | 의심 포트·삭제된 열린 파일·프로세스 점검 |
| `/var/log/secure` 또는 `/var/log/auth.log` | 인증·로그인·sudo 등 보안 이벤트 | 배포판별 인증 실패·권한 사용 확인 |
| `/var/log/messages` 또는 `/var/log/syslog` | 시스템·서비스 일반 메시지 | 서비스 오류·시스템 이상 확인 |
| `/var/log/audit/audit.log` | auditd 감사 이벤트 | 보안 정책·시스템 호출·객체 접근 추적 |

- 로그 파일명과 저장 위치는 배포판·로깅 구성에 따라 다르다. 시험에서는 문제에 제시된 운영체제와 로그 형식을 우선하고, `누가·언제·어디서·무엇을·성공/실패했는가`를 기준으로 읽는다.

**[답안]** `btmp`/`lastb`는 로그인 실패 흔적을 확인하는 데 사용한다. 다수의 실패가 반복되면 무차별 대입 또는 계정 오남용 가능성을 판단하고, 계정 잠금·접근원 제한·로그 보존·원인 조사를 수행한다.

### 1.1.5 [P2] inode 시간·프로세스·메모리 취약점

- `atime`: 마지막 접근 시간, `mtime`: 파일 내용 변경 시간, `ctime`: inode 메타데이터 변경 시간이다. `ctime`은 생성 시간이 아니다.
- 프로세스는 일반적으로 `fork()`로 생성한 뒤 `exec()` 계열 호출로 새 프로그램 이미지를 적재한다.
  - `SIGINT(2)`: 인터럽트, `SIGKILL(9)`: 강제 종료, `SIGSTOP(19)`: 정지
- `/proc`는 실행 중인 프로세스와 커널 상태를 파일 형태로 노출하는 가상 파일시스템이다. PID 디렉터리, 명령행, 열린 파일, 메모리·네트워크 상태를 확인하는 단서로 사용한다.
- 버퍼 오버플로우는 버퍼 경계를 넘는 입력이 인접 메모리를 덮어써 프로그램 흐름·데이터를 훼손할 수 있는 취약점이다.
  - 원인: 길이 검증 없는 복사·입력 처리
  - 대응: 입력 길이·형식 검증, 안전한 API와 오류 처리, 컴파일러 보호(stack canary), ASLR, NX/DEP, 패치
  - `strncpy()`만 사용한다고 자동으로 안전해지는 것은 아니다. 종료 문자·버퍼 길이를 함께 확인해야 한다.

## 1.2 [P1] Linux 서버 보안설정 점검과 보완

### 1.2.1 [P1] 서비스 최소화와 xinetd 설정

- 원칙: 사용하지 않는 서비스·계정·포트는 제거 또는 비활성화하고, 필요한 서비스만 허용 대상·시간·동시 연결 수를 제한한다.
- xinetd는 요청이 들어올 때 서비스를 실행·관리하는 슈퍼 데몬이다. 최신 배포판은 systemd를 주로 사용하지만, 시험에서는 xinetd 설정 해석이 반복된다.

| 지시어 | 의미 | 보안 판단 |
|---|---|---|
| `disable = yes/no` | 서비스 비활성화/활성화 | 불필요 서비스는 `yes`로 비활성화 |
| `only_from = IP` | 허용 원본 IP·대역 | 관리망 등 필요한 대상만 허용 |
| `no_access = IP` | 차단 원본 IP·대역 | 알려진 비인가 대역 차단 |
| `access_times = 09:00-18:00` | 서비스 허용 시간 | 불필요한 야간 노출 축소 |
| `instances = 10` | 최대 동시 인스턴스 | 자원 고갈 완화 |
| `per_source = 3` | 원본별 최대 연결 수 | 단일 출발지의 과도한 연결 완화 |
| `cps = 50 10` | 초당 연결 한도·초과 시 대기 | 과도한 연결 시도 완화 |

- TCP Wrapper의 `hosts.allow`, `hosts.deny`는 libwrap을 사용하는 레거시 서비스의 IP 기반 접근통제 수단이다. 시험에서는 **허용 우선·차단 정책과 IP 제한 목적**을 이해한다.

### 1.2.2 [P1] 계정·권한·파일 점검

| 점검 대상 | 취약 상태 | 보완 방향 |
|---|---|---|
| 계정 | 불필요 계정, 공유 계정, 미사용 관리자 계정 | 제거·잠금·개인별 계정 발급·권한 정기 검토 |
| 패스워드 | 짧음, 재사용, 실패 잠금 미설정 | PAM 품질·만료·실패 잠금 정책 적용 |
| 파일·디렉터리 | world-writable, 과도한 SUID/SGID, 소유자 없음 | 최소권한·소유자 정정·불필요 특수권한 제거 |
| 중요 파일 | 패스워드·설정 파일의 과도한 읽기/쓰기 권한 | 관리자만 변경·필요 최소 사용자만 읽기 |
| 무결성 | 기준 파일과 현재 파일이 다름 | 변경 승인 여부 확인, Tripwire 등으로 기준선 비교 |

- 점검 명령◊은 1.1.3의 `find`, `chmod`, `chown`, `umask`를 사용한다. 점검 결과를 발견하는 데서 끝내지 말고 `업무상 필요 여부 확인 → 소유자·권한 정정 → 변경 기록 → 재점검` 순서로 처리한다.
- `find -perm -MODE`은 MODE의 모든 비트가 설정된 대상을, `find -perm /MODE`은 MODE 중 하나 이상이 설정된 대상을 찾는다.

### 1.2.3 [P1] 로그·원격접속·버전·패치 점검

- 먼저 운영체제와 서비스 버전을 식별한 뒤 지원 종료·알려진 취약점·패치 상태를 판단한다.

```bash
# Linux 운영체제·커널 정보
cat /etc/os-release
uname -a

# Windows 운영체제 정보
systeminfo
```

| 점검 축 | 확인할 증거 | 대표 보완 |
|---|---|---|
| 로그 | 로그인 성공/실패, 권한 변경, 서비스 오류, 비정상 프로세스 | 로그 생성·보관·권한 제한·정기 분석 |
| 원격접속 | Telnet·rlogin 등 평문 서비스, root 직접 로그인 | SSH 등 안전한 프로토콜 사용, root 직접 로그인 제한, 관리 IP 제한 |
| 버전 노출 | 배너·오류 페이지·서비스 응답의 OS/미들웨어 버전 | 불필요한 배너/상세 오류 제거, 최신 보안 패치 적용 |
| 패치 | 지원 종료 버전, 알려진 취약 버전, 누락된 업데이트 | 자산·버전 식별 → 영향 평가 → 테스트 → 배포 → 결과 기록 |
| 백업·복구 | 복구 불가·검증되지 않은 백업 | 중요 설정·로그·데이터의 백업과 복구 시험 |

- Linux root 원격접속 관련 대표 점검:
  - `/etc/securetty`: root가 직접 로그인할 수 있는 터미널을 제한하는 레거시/Unix 계열 설정과 연결한다.
  - SSH는 `sshd_config`의 `PermitRootLogin` 등 root 로그인 허용 여부와 관리 IP·인증 방식을 점검한다. root 직접 로그인이 필요하지 않다면 `PermitRootLogin no`를 검토하되, 변경 전에는 운영체제·OpenSSH 버전과 대체 관리자 접근 경로를 확인한다.
  - Telnet·FTP처럼 인증정보와 데이터가 평문으로 노출될 수 있는 서비스는 SSH·SFTP/FTPS 등 안전한 대안과 접근제어를 적용한다.

**[답안 템플릿]** `[설정/로그]는 [위험]을 발생시킬 수 있다. [근거] 때문에 비인가 접근·권한 상승·정보 노출 가능성이 있다. 따라서 [서비스/계정/권한]을 최소화하고 [구체적 설정·패치·로그 점검]을 적용한다.`

## 1.3 [P1] Windows 인증·접근통제·감사

### 1.3.1 [P2] Windows 보안 구성요소

| 구성요소 | 역할 | 시험 포인트 |
|---|---|---|
| LSA/LSASS | 로컬 보안 정책과 인증 절차를 관리 | 인증·보안 정책의 중심 |
| SAM | 로컬 계정과 패스워드 해시 정보를 관리 | 로컬 계정 정보 보호 |
| SRM | 커널 수준의 접근 토큰·ACL 검사와 감사 이벤트 생성에 관여 | 객체 접근통제·감사 |
| SID | 보안 주체를 식별하는 고유 식별자 | 계정 생성 시 부여되고, 로그인 시 새로 발급되는 값이 아님 |

- LM 해시는 오래된 DES 기반 방식으로 취약하다. NTLM 계열은 챌린지/응답 방식이며, 도메인 환경에서는 Kerberos가 주된 인증 방식이다.
- 계정 보안의 핵심은 기본 Administrator 계정 보호, Guest 비활성화, 최소권한 그룹 부여, 계정 공유 금지, 로그인·권한 변경 감사다.
- 잘 알려진 RID: Administrator는 `500`, Guest는 `501`이다. 일반 계정의 RID는 환경에 따라 달라지므로 특정 숫자 범위를 보안 판단 근거로 단정하지 않는다.
- UAC(User Account Control)는 관리자 권한이 필요한 작업에서 권한 상승을 확인·통제한다. UAC 팝업이 나타났다는 사실만으로 악성행위를 단정하지 않고, 실행 파일·게시자·요청한 작업·사용자 의도를 함께 확인한다.

### 1.3.2 [P1] NTFS 권한·암호화·이벤트 로그

- NTFS ACL은 사용자·그룹별 권한을 제어한다. 공유 권한과 NTFS 권한이 함께 적용될 수 있으므로, 최소권한 원칙으로 불필요한 쓰기·변경 권한을 제거한다.
- EFS는 NTFS 파일·폴더 단위 암호화 기능이고, BitLocker는 볼륨 단위 암호화 기능이다. 둘은 적용 단위와 운영 목적이 다르다.
- 이벤트 뷰어(`eventvwr.msc`)에서 `Security`, `System`, `Application` 로그를 중심으로 로그인 성공·실패, 계정 관리, 개체 접근, 정책 변경, 시스템·응용 프로그램 오류를 확인한다.
- 로그는 필요한 보관 기간과 용량을 정하고, 덮어쓰기·삭제·변조 위험을 줄이며 중앙 수집 또는 별도 보관을 고려한다.
- 로그 용량 계산형은 문제에서 준 단위로 계산한다.

```text
필요 로그 용량 = 이벤트 1건의 크기 × 일일 발생 건수 × 보관 일수
```

단위가 byte로 주어졌다면 마지막에 KB/MB 변환 요구가 있는지 확인하고, 이벤트 뷰어의 해당 로그 속성에서 최대 로그 크기와 덮어쓰기 정책을 함께 설정한다.

## 1.4 [P1] Windows 서버 보안설정 점검과 보완

### 1.4.1 [P1] NetBIOS·공유·원격 세션

- NetBIOS over TCP/IP가 필요하지 않은 환경에서는 비활성화를 검토한다. 비활성화 전에는 레거시 WINS/NetBT 의존 서비스가 없는지 확인해야 한다.
- 대표 경로: `ncpa.cpl` → 네트워크 어댑터 속성 → `Internet Protocol Version 4 (TCP/IPv4)` → 고급 → WINS → `NetBIOS over TCP/IP 사용 안 함`.
- 공유·세션 점검 명령:

```bat
net share
net session
net session \\대상컴퓨터 /delete
```

- 보안 판단: 불필요한 관리 공유, Administrator 등 과도한 권한의 원격 로그인, 구형 평문 원격 서비스, 상세 버전 배너는 공격면을 넓힌다. 필요한 관리망·관리자·프로토콜만 허용하고, 원격접속·공유·계정 활동을 감사한다.

## 1.5 [P2] 무결성·악성코드·취약점 대응

- 파일 무결성 점검은 기준선의 파일 해시·속성·권한과 현재 상태를 비교해 비인가 변경을 탐지한다. Tripwire는 대표적인 무결성 점검 도구다.
- 취약점 진단 도구는 알려진 취약 설정·버전·서비스를 찾아내는 데 도움을 주지만, 결과의 오탐·영향도·업무상 예외를 사람이 검토해야 한다.
- 악성코드·침해 의심 시에는 증거 보존, 범위 확인, 격리, 원인 제거·패치, 자격증명 교체, 복구·재발 방지의 순서로 대응한다. 운영 중인 시스템을 즉시 임의로 삭제·재부팅하는 것은 증거와 업무 영향을 고려해 판단한다.

| 유형 | 핵심 판단 | 대표 대응 |
|---|---|---|
| 권한 상승 | 일반 계정·프로세스가 관리자/root 권한을 획득 | 취약점·과도한 권한·SUID/UAC 설정 확인, 패치·최소권한 |
| 백도어·트로이목마 | 정상 프로그램·서비스로 위장하거나 비인가 접근 경로 생성 | 실행 파일·서비스·네트워크 연결·지속성 점검, 격리·제거·자격증명 교체 |
| 루트킷 | 프로세스·파일·네트워크 흔적을 은닉하고 높은 권한 유지 | 신뢰 가능한 외부 환경·무결성 기준선으로 확인, 필요 시 안전한 재설치 |
| 랜섬웨어 | 파일 암호화·업무 중단·금전 요구 | 확산 격리, 증거 보존, 오프라인 백업 복구, 침투 원인 제거 |
| 무차별 대입 | 짧은 시간에 다수 인증 실패 | 실패 로그 확인, 잠금·MFA·접근원 제한·비밀번호 변경 |

### 1.7.1 Windows 레지스트리 하이브

| 약어 | 정식 이름 | 핵심 역할 |
|---|---|---|
| `HKLM` | `HKEY_LOCAL_MACHINE` | 컴퓨터 전체의 하드웨어·운영체제·소프트웨어 설정 |
| `HKCU` | `HKEY_CURRENT_USER` | 현재 로그인 사용자의 환경 설정 |

- 보안 관점: 레지스트리의 자동 실행, 서비스, 보안 정책 변경은 침해 흔적 또는 지속성 단서가 될 수 있다. 값 변경 전에는 기준선·변경 이력·영향 범위를 확인한다.

### 1.7.2 Windows 기본 보안 주체와 그룹

| 주체/그룹 | 시험용 핵심 의미 | 보안 유의점 |
|---|---|---|
| `Administrator` | 로컬 시스템 관리 권한을 가진 기본 계정 | 이름 변경만으로 보호되지 않으며, 강한 인증·사용 통제·감사가 필요 |
| `Guest` | 제한된 임시 사용자 계정 | 특별한 사유가 없으면 비활성화 |
| `SYSTEM` | 운영체제와 서비스가 사용하는 매우 높은 권한의 보안 주체 | 일반 사용자 계정에 부여하면 안 됨 |
| `Administrators` | 시스템 전반 관리 권한 그룹 | 구성원을 최소화하고 정기 검토 |
| `Users` | 일반 사용자 권한 그룹 | 업무에 필요한 권한만 추가 부여 |
| `Backup Operators` | 백업·복원 관련 권한 그룹 | 데이터 접근 우회 가능성을 고려해 최소 인원만 부여 |
| `Account Operators` | 계정·그룹 관리 권한을 가진 그룹 | 권한 상승 경로가 될 수 있어 사용 범위 제한 |

### 1.7.3 Linux 프로세스와 PCB

- PCB(Process Control Block)는 운영체제가 프로세스를 관리하기 위해 유지하는 제어 정보다.
- 대표 정보: 프로세스 상태, PID, 프로그램 카운터·레지스터 등 실행 문맥, 스케줄링 정보, 메모리·파일·권한 관련 정보.
- `fork()`는 새 프로세스 생성, `exec()` 계열은 현재 프로세스의 프로그램 이미지를 다른 프로그램으로 교체하는 흐름으로 이해한다.
- 시험에서는 PCB의 모든 필드 암기보다 **프로세스 식별·권한·실행 이력·비정상 프로세스 점검**과 연결한다.

### 1.7.4 PAM·패스워드 정책의 배포판별 세부

- `pam_pwquality`는 현대 RHEL 계열에서 널리 쓰이는 패스워드 품질 모듈이고, 오래된 자료에는 `pam_cracklib`가 보일 수 있다. 문제에서 주어진 모듈명·경로를 그대로 답한다.
- PAM 설정 위치는 배포판에 따라 다르다. 예를 들어 RHEL 계열은 `system-auth`/`password-auth` 구성이, Debian 계열은 `common-auth` 등 구성이 보일 수 있다.
- 자주 보는 정책 키: `minlen`, `minclass`, `retry`, `difok`, `deny`, `unlock_time`, `TMOUT`, `PASS_MAX_DAYS`, `PASS_MIN_DAYS`, `PASS_WARN_AGE`.
- 숫자 자체를 보편 정답으로 외우지 않는다. “최소 길이 강화”, “연속 실패 잠금”, “유휴 세션 종료”, “패스워드 재사용·만료 통제”라는 목적과 문제의 값을 연결한다.

### 1.7.5 레거시 서비스·명령 세부

- TCP Wrapper: libwrap을 사용하는 서비스에서 `hosts.allow`, `hosts.deny`로 접근을 제한하는 레거시 방식이다.
- `net share`는 공유 목록 확인, `net session`은 서버 세션 확인에 사용한다. 실제 운영 명령은 대상·권한·영향을 확인한 뒤 수행한다.
- `EFS`와 `BitLocker`의 차이, LM/NTLM/Kerberos의 세부 프로토콜 비교, 레지스트리 자동 실행 위치는 시간이 남을 때 P3 기출과 함께 확장한다.

### 1.7.6 P3 학습 완료 기준

1. 레지스트리 하이브 5개를 역할과 함께 구분한다.
2. Administrator·Guest·SYSTEM·Administrators·Users·Backup Operators의 권한 위험을 한 줄로 설명한다.
3. PCB의 목적과 `fork()`/`exec()` 차이를 설명한다.
4. 배포판별 PAM 경로·모듈명이 달라도 정책 목적은 같음을 설명한다.

## 1.8 이 장만 보는 최종 회독 순서

### 1회독: 논리 흐름 이해

`계정 식별 → 인증 정책 → 권한 부여 → 로그 기록 → 취약 설정 점검 → 보완·재점검` 흐름으로 읽는다. 명령어를 따로 외우기보다 각 명령이 이 흐름의 어느 증거를 확인하거나 통제하는지 연결한다.

### 2회독: P1 회상 연습

아래 질문을 문서를 가리고 답한다.

1. `/etc/passwd`, `/etc/shadow`, `/etc/group`의 역할과 주요 필드는 무엇인가?
2. PAM의 네 유형과 패스워드 품질·실패 잠금·세션 종료 정책은 어떻게 연결되는가?
3. SUID·SGID·sticky bit의 의미와 위험한 파일을 찾는 명령은 무엇인가?
4. `utmp/wtmp/btmp/lastlog`와 `last/lastb/lastcomm/lsof`는 무엇을 확인하는가?
5. `only_from`, `no_access`, `instances`, `access_times`가 제한하는 것은 무엇인가?
6. 불필요 계정·평문 원격서비스·버전 노출·패치 누락을 어떻게 점검하고 보완하는가?
7. LSA/LSASS·SAM·SRM·SID의 역할과 NTFS ACL의 보안 목적은 무엇인가?
8. NetBIOS·Windows 공유·원격 세션·이벤트 로그를 어떻게 점검하는가?
9. Tripwire 같은 무결성 도구와 취약점 진단 도구의 목적은 어떻게 다른가?

### 3회독: 답안 작성 연습

- 단답형: 용어·경로·명령을 정확히 쓴다.
- 서술형: `정의/상태 → 위험/판단근거 → 설정·조치` 세 단으로 쓴다.
- 실무형: 먼저 소문항 수를 세고, 각 번호에 `증거·판단·조치`를 빠짐없이 대응한다.

### 학습 완료 판정

- P1 즉답 목록을 90% 이상 설명할 수 있다.
- 위 9개 질문 중 7개 이상을 자료 없이 답할 수 있다.
- Linux 설정형 1문제와 Windows 로그·설정형 1문제를 각각 15분 안에 서술할 수 있다.
- 틀린 항목은 해당 본문으로 돌아가 보완하고, P3는 P1 기준을 충족한 뒤 학습한다.
