# 5 정보보호 관리 및 법규

> 목표: 조직의 정보자산과 위험을 식별하고, 적절한 보호대책·업무연속성·사고대응·법적 요구사항을 사례에 적용하여 **채점 가능한 답안**으로 쓴다.

> **검증일: 2026-07-12 / 시험 적용일: 2026-07-18.** 정보보안기사의 2026년 정기 기사 제2회 실기시험일에 시행 중인 법령·고시를 기준으로 한다.
>
> 시험일 뒤 시행되는 2026-08-20·09-11 등의 개정 조항은 이번 시험의 현행 답으로 사용하지 않는다.

> 이 문서는 5장 개념 복습의 기준 문서다. PDF를 다시 대조할 필요는 없지만, 법령은 이후 시험을 준비할 때 시행일을 다시 확인해야 한다.

## 0. 학습 우선순위와 출제 패턴

### 태그 규칙

- **[P1]**: 정의·절차·수치·차이를 자료 없이 써야 하는 합격 핵심. 1회독부터 학습한다.
- **[P2]**: P1의 사례·예외·비교 확장. P1을 재현한 다음 학습한다.
- **[P3]**: 저빈도·연혁·세부 제도. 시간이 부족하면 건너뛰어도 된다.
- **[답안]**: 단답·서술·실무형에서 그대로 재구성할 문장이다.

### 한눈에 보는 논리 흐름

```text
경영목표·법적 요구
       ↓
범위·정책·자산 식별 → 위협·취약점·위험 평가 → 위험처리·보호대책
       ↓                                      ↓
역할·교육·감사                        BCP·DRP·백업
       └──────── 사고 예방·탐지·대응·복구 ────────┘
                              ↓
                     증거보존·개선·인증·준거성
```

### 문제를 읽기 위한 최소 용어

| 용어 | 뜻 | 관계 |
|---|---|---|
| 자산(Asset) | 조직이 가치를 부여하고 보호해야 할 대상 | 정보·HW·SW·인력·시설·서비스 포함 |
| 위협(Threat) | 자산에 손해를 일으킬 잠재 원인 | 공격자·재난·오류 등 |
| 취약점(Vulnerability) | 위협이 이용할 수 있는 약점 | 패치 미적용·잘못된 권한·절차 부재 등 |
| 위험(Risk) | 불확실성이 목표에 미치는 영향 | 보통 가능성×영향으로 평가 |
| 통제(Control) | 위험을 수정하는 정책·절차·기술 | 예방·탐지·교정 또는 관리·물리·기술 |
| 잔여위험 | 통제 적용 뒤 남은 위험 | 위험수용기준과 비교 |
| 준거성 | 법령·계약·정책·표준 요구를 지키는 상태 | 기술 안전성만으로 충족되지 않음 |
| 개인정보처리자 | 업무 목적으로 개인정보파일을 운용하며 개인정보를 처리하는 주체 | 조직·기관·개인 등 |
| 개인정보취급자 | 처리자의 지휘·감독을 받아 개인정보를 처리하는 사람 | 임직원·파견·시간제근로자 등 |

### 근거 기반 우선순위

| 우선순위 | 학습 묶음 | 출제 형태 |
|---|---|---|
| P1 | 위험관리 | 단계 배열, 접근법 비교, 정량 계산, 4대 처리 |
| P1 | 개인정보보호법·안전성 확보조치 | 정의, 동의, 가명정보, 유출, 접속기록, CCTV 사례 |
| P1 | 관리체계·ISMS-P | PDCA, 정책·자산·역할, 인증 3영역과 현행 개수 |
| P1 | BCP·DRP·백업 | BIA, RTO/RPO/MTD/WRT, 복구센터·백업 비교 |
| P1/P2 | 사고대응·공격 생명주기·포렌식 | 대응 순서·증거 원칙은 P1, Kill Chain·ATT&CK 비교는 P2 |
| P1/P2 | 정보보호 법제 | 정보통신망법의 침해사고·IDC 핵심은 P1, 기반보호법·전자서명법·저작권 세부는 P2 |
| P3 | 인증 연혁·윤리·저빈도 세부 수치 | 단답형 식별 |

> 1~31회 복원 513문항 중 관리·법규 분류는 156문항(30.4%)으로 가장 크고, 최근 23~31회도 44/162문항(27.2%)이다.
>
> 이 장을 버리는 전략은 합격점 전략이 아니다. 조문 번호 전체보다 `주체-요건-행위-기한-조치`를 우선한다.

### 반복 출제 패턴

1. **정의·관계형**: 자산·위협·취약점·위험, 처리자·취급자, 가명·익명을 구분한다.
2. **절차 배열형**: 위험관리, 사고대응, 포렌식, BCP 수립 순서를 묻는다.
3. **계산형**: `SLE=AV×EF`, `ALE=SLE×ARO`를 계산하고 대책 비용과 비교한다.
4. **비교형**: 위험처리 4종, 정량/정성, RTO/RPO, 백업·복구센터, Kill Chain/ATT&CK를 비교한다.
5. **법규 사례형**: 동의 항목, 유출 통지·신고, CCTV, 접속기록 의무를 사례에 적용한다.
6. **인증 빈칸형**: ISMS-P 영역·분야·기준 수, ISMS와의 차이를 채운다.

### 오래된 기출을 풀 때의 현행성 규칙

- 문제에 **당시 기준**이라고 쓰였으면 출제 당시 법령으로 답한다.
- 2026년 시험의 현행 기준을 묻는다면 이 문서의 시험 적용일 수치를 쓴다.
- ISMS-P의 과거 `102개`는 개정 전 수치다. 2026-07-18 적용 기준은 **3영역·21분야·101개(16+64+21)**다.
- 벌칙·과태료 액수는 개정 변동성이 크므로 문제가 조문과 조건을 제시하지 않으면 P1 암기에서 제외한다.

### 1~4장과의 경계

- OS·네트워크·웹의 공격과 설정 명령은 1~3장, 이 장은 조직적 통제·사고 절차·법적 의무를 다룬다.
- 암호·인증·접근통제·전자서명·PKI의 기술 원리는 4장, 정책·인증제도·법적 효력은 5장이다.
- 로그 생성 명령은 1~3장, 로그 정책·접속기록 보존·증거 관리는 5장이다.

## 5.1 [P1] 정보보호 관리체계·거버넌스·정책

### 5.1.1 [P1] 정보보호 목표와 확장 속성

| 속성 | 의미 | 대표 통제 |
|---|---|---|
| 기밀성(Confidentiality) | 인가된 주체만 정보에 접근 | 암호화·접근통제 |
| 무결성(Integrity) | 비인가 변경·파괴를 방지하고 정확성 유지 | 해시·MAC·변경관리 |
| 가용성(Availability) | 필요할 때 정보·서비스 사용 가능 | 이중화·백업·DR |
| 인증성 | 주체·메시지 출처가 주장과 일치 | MFA·전자서명 |
| 책임추적성 | 행위를 특정 주체까지 추적 | 개인계정·로그·감사 |
| 부인방지 | 송수신·행위 사실의 사후 부인을 어렵게 함 | 전자서명·시각·증거관리 |

정보보호는 기술 설치가 아니라 **업무 목표와 허용 위험수준을 만족시키는 지속적 관리활동**이다. CIA 사이에는 비용·편의·성능의 상충이 있으므로 자산 중요도와 위험에 비례해 통제를 정한다.

### 5.1.2 [P1] PDCA와 거버넌스

| 단계 | 핵심 활동 |
|---|---|
| Plan | 범위·정책·목표·위험수용기준 설정, 자산·위험 평가, 대책 계획 |
| Do | 통제 구현·운영, 교육, 문서화 |
| Check | 모니터링·성과측정·내부감사·준거성 검토·경영진 검토 |
| Act | 부적합 원인 시정, 지속 개선과 다음 계획 반영 |

- 이사회·최고경영진은 방향, 자원, 책임, 위험수용을 승인한다.
- CISO는 정보보호 전략·정책·조직·위험관리·사고대응을 총괄하며, 시험에서는 다음 역할을 묶어 쓴다.
  1. 정보보호 관리체계와 정책을 수립·시행하고 지속 개선한다.
  2. 정보자산의 위험을 식별·평가하고 보호대책을 선정·이행한다.
  3. 임직원 교육, 인식제고, 사고대응 훈련·모의훈련을 실시한다.
  4. 침해사고 예방·대응과 법령상 필요한 보호조치·보고를 관리한다.
- CPO는 개인정보 처리와 보호, 불만·피해구제, 내부통제 등을 총괄한다. 두 역할은 목적이 겹쳐도 법적 역할을 구분해 쓴다.
- 실무조직은 통제를 운영하고, 내부감사는 운영부서로부터 독립적으로 적정성과 효과성을 평가한다.
- 직무분리, 최소권한, 상호검토로 한 사람이 승인·실행·검증을 모두 수행하지 않게 한다.

### 5.1.3 [P1] 문서 체계와 생명주기

```text
정책(무엇을·왜) → 표준/지침(공통 기준·방법) → 절차(누가·언제·어떻게) → 기록(수행 증거)
```

문서는 승인권자·책임자·버전·시행일·검토주기·배포대상을 명확히 하고, 법령·조직·기술·사고 변화 시 재검토한다. 폐기 문서는 오용되지 않도록 회수·표시하고 필요한 기간 보존한다.

**기출형 정보보호 방침·실행계획**

1. 정보보호 목표·범위·책임과 법·규제·계약·정책·기술 요구를 방침으로 문서화해 시행한다.
2. 방침을 토대로 예산·일정을 포함한 당해 연도 실행계획을 수립한다.
3. 최고경영층이 실행계획을 승인하고 CISO가 추진상황을 매 반기 점검한다.

> `매 반기`는 해당 기출이 제시한 정보보호조치 지침 문맥의 답이다. 현행 법령 일반의 모든 조직에 같은 주기를 확대 적용하지 않는다.

### 5.1.4 [P1] 정보자산 관리

1. 관리체계 범위와 업무 프로세스를 정한다.
2. 정보·HW·SW·서비스·인력·시설·문서 등 자산을 식별하고 목록화한다.
3. 자산소유자와 관리자를 지정한다.
4. 기밀성·무결성·가용성 및 법적 요구에 따라 중요도·등급을 정한다.
5. 등급에 맞는 취급·접근·보관·전송·백업·파기 기준을 적용한다.
6. 변경·이동·반출·폐기 이력을 관리하고 정기적으로 현행화한다.

유형·보안특성·중요도와 적용 위협·취약점이 유사한 자산은 그룹핑할 수 있다. 같은 분석을 반복하지 않고 공통 보호대책을 일관되게 적용하되, 그룹 안의 고위험 자산이 평균값에 가려지지 않게 예외를 분리한다.

**[답안]** 자산 식별은 장비 목록 작성으로 끝나지 않는다. 업무와 정보 흐름을 기준으로 자산을 식별하고 소유자·중요도·법적 요구를 부여한 뒤, 생명주기별 보호기준과 현행화 절차를 적용한다.

## 5.2 [P1] 위험관리·위험평가

### 5.2.1 [P1] 위험 구성요소

```text
위협이 취약점을 이용 → 자산에 사고 발생 → 기밀성·무결성·가용성 및 업무에 영향
위험수준 ≈ 발생가능성 × 영향도
```

- 위협이 있어도 이용할 취약점이 없거나 영향이 미미하면 위험은 낮을 수 있다.
- 취약점은 그 자체가 사고가 아니라 약점이다.
- 통제는 가능성·영향을 낮추지만 보통 위험을 완전히 0으로 만들지는 않는다.
- 고유위험은 통제 전, 잔여위험은 통제 후 위험이다.

### 5.2.2 [P1] 위험관리 절차

**위험관리계획**은 위험관리의 방법·절차, 수행인력과 책임, 기간·대상·범위, 평가방법, 예산·자원을 구체화한 문서다.

```text
상황·범위·기준 수립
→ 자산 식별·가치평가
→ 위협·취약점·기존통제 식별
→ 가능성·영향 분석
→ 위험수준 산정·우선순위 평가
→ 위험처리 선택·계획·승인
→ 통제 구현
→ 잔여위험 승인
→ 지속 모니터링·재평가
```

문제에서 4~5단계로 단순화해도 핵심은 `식별 → 분석 → 평가 → 처리 → 모니터링`이다. 분석은 위험의 크기를 산정하고, 평가는 기준과 비교하여 처리 우선순위를 결정한다.

**기출형 6단계 라벨**

```text
위험관리 전략·계획 수립 → 위험분석 → 위험평가
→ 보호대책 선정 → 정보보호계획 수립 → 보호대책 실행
```

위의 지속관리 절차를 시험 빈칸형으로 압축한 표현이다. 실행 후에는 모니터링·재평가로 순환한다.

### 5.2.3 [P1] 평가 접근법

| 접근법 | 방법 | 장점 | 한계 |
|---|---|---|---|
| 기준선(Baseline) | 모든 대상에 표준 보호수준 적용 | 빠르고 일관됨 | 조직별 고유 위험 반영 부족 |
| 비정형(Informal) | 전문가 경험·판단 중심 | 빠르고 유연함 | 재현성·객관성 낮음 |
| 상세(Detailed) | 자산별 위협·취약점·영향을 정밀 분석 | 정확·근거 명확 | 시간·비용 큼 |
| 복합(Combined) | 고위험은 상세, 나머지는 기준선 등 혼합 | 비용과 정확성 균형 | 분류기준 필요 |

| 분석법 | 결과 | 적합한 상황 |
|---|---|---|
| 정량 | 금액·횟수 등 수치 | 손실·발생빈도 자료가 신뢰 가능할 때 |
| 정성 | 상·중·하, 점수, 위험행렬 | 자료 부족, 빠른 합의·우선순위 필요 |
| 반정량 | 서열 점수에 정의된 척도 적용 | 비교 가능성과 현실성을 함께 확보 |

**개별 분석기법 식별**

| 기법 | 핵심 식별어 |
|---|---|
| 델파이법 | 여러 전문가가 익명·반복적으로 의견을 제시하고 피드백을 거쳐 합의에 수렴 |
| 시나리오법 | 발생 가능한 사고 시나리오를 구성해 원인·영향·대응을 분석 |
| 순위결정법 | 비교 기준에 따라 위험 항목의 상대 순위와 우선순위를 결정 |
| 확률분포법 | 손실·발생빈도의 확률분포로 기대손실과 불확실성을 추정 |
| 퍼지행렬법 | 정확한 수치가 어려운 판단을 퍼지 소속도와 행렬로 종합 |

델파이는 단순 다수결이나 한 번의 전문가 회의가 아니다. 익명성·반복·통제된 피드백·의견 수렴이 식별어다.

### 5.2.4 [P1] 정량 계산

| 기호 | 의미 | 식 |
|---|---|---|
| AV | 자산가치 | 주어진 금액 |
| EF | 1회 사고 시 손실비율 | 0~1 또는 % |
| SLE | 1회 예상손실액 | `AV × EF` |
| ARO | 연간 예상발생률 | 연간 횟수 |
| ALE | 연간 예상손실액 | `SLE × ARO` |

```text
AV=1억원, EF=40%, ARO=0.5회/년
SLE=1억×0.4=4천만원
ALE=4천만원×0.5=2천만원/년
```

대책 도입의 단순 경제성은 `(도입 전 ALE - 도입 후 ALE) - 연간 대책비용`으로 판단할 수 있다. 그러나 생명·법적 의무·평판처럼 금액화가 어려운 영향은 정성 판단을 병행한다. ALE가 대책비보다 작다는 이유만으로 법적 필수 통제를 생략할 수 없다.

```text
ROSI(%) = (도입 전 ALE - 도입 후 ALE - 연간 대책비용) / 연간 대책비용 × 100
```

ROSI가 양수면 계량한 조건에서는 비용 대비 손실감소 효과가 있다는 뜻이다. 계산에 포함하지 못한 법적·평판 위험과 추정 오차를 별도로 검토한다.

### 5.2.5 [P1] 위험처리 4종

| 처리 | 뜻 | 예 |
|---|---|---|
| 감소/완화 | 통제로 가능성·영향을 낮춤 | MFA·패치·이중화 |
| 회피 | 위험을 만드는 활동을 중단·변경 | 취약한 서비스 폐지 |
| 전가/공유 | 계약·보험·외부서비스로 손실 일부 이전 | 사이버보험·SLA |
| 수용 | 기준 이내 위험을 권한자가 알고 승인 | 문서화 후 모니터링 |

- 전가는 책임 전체를 없애지 않는다. 위탁자·개인정보처리자의 법적 책임과 감독의무는 남을 수 있다.
- 수용은 방치가 아니라 근거·승인·기한·모니터링이 있는 의사결정이다.
- 보호대책명세서(SoA)는 적용 통제, 선택 근거, 구현 상태와 제외 근거를 추적한다.

**[답안]** 위험수용기준과 비교해 허용할 수 없으면 감소·회피·전가 중 처리방안을 선택하고 책임자·기한·자원을 명시한다. 적용 후 잔여위험을 재평가하여 권한자가 승인하고 지속 모니터링한다.

## 5.3 [P1] 보호대책·업무연속성·재해복구

### 5.3.1 [P1] 통제 분류

| 관점 | 구분 | 예 |
|---|---|---|
| 구현 수단 | 관리적 | 정책·교육·직무분리·감사·계약 |
|  | 물리적 | 보호구역·출입통제·CCTV·환경설비 |
|  | 기술적 | 인증·접근통제·암호화·방화벽·로그 |
| 시점·목적 | 예방 | 사고 가능성 차단·감소 |
|  | 탐지 | 이상·사고를 발견·경보 |
|  | 교정/복구 | 원인 제거·정상 복원·재발 방지 |

하나의 통제는 두 분류에 동시에 속할 수 있다. 예를 들어 CCTV는 물리적 통제이면서 탐지·억제 통제다. 단일 통제에 의존하지 않고 사람·절차·기술을 계층화하는 심층방어를 적용한다.

- **물리적 접근통제**는 건물·보호구역·설비·매체에 대한 사람의 출입·접근을 제한한다.
- **논리적 접근통제**는 계정·인증·권한으로 시스템·응용프로그램·데이터 접근을 제한한다.

### 5.3.2 [P1] 인적·외부자·물리 보안

- **입사 전**: 직무별 자격 확인, 법이 허용하는 범위의 신원검증, 비밀유지·보안책임 명시.
- **재직 중**: 최소권한, 직무분리, 정기·직무별 교육, 권한 검토, 위반·사고 보고.
- **직무변경·퇴직**: 즉시 권한 변경·회수, 계정·출입증·장비·자료 반납, 비밀유지 의무 고지.
- **외부자**: 선정 위험평가, 계약에 보안요구·재위탁·사고통지·감사·반환·파기·종료조치 명시, 수행 중 감독.
- **물리**: 제한·통제·접견 구역을 구분하고 출입승인·기록·방문자 동행, 전력·화재·온습도·누수 대응, 매체 반출·폐기를 통제한다.

교육은 `계획 → 실시 → 참여·결과 기록 → 효과평가 → 개선`으로 관리한다. 감사는 기준·범위·독립성·증거·부적합·시정조치와 완료 확인까지 포함한다.

### 5.3.3 [P1] BIA·BCP·DRP

| 용어 | 뜻 |
|---|---|
| BIA | 업무 중단의 시간별 영향과 핵심업무·자원·의존성을 분석 |
| BCP | 재해 중에도 핵심업무를 허용수준으로 지속·복구하는 전사 계획 |
| DRP | 정보시스템·데이터·시설 복구에 초점을 둔 BCP의 하위 계획 |
| MTD/MAO | 업무가 감내할 수 있는 최대 중단시간 |
| RTO | 사고 후 서비스를 복구해야 하는 목표시간 |
| WRT | IT 복구 뒤 업무 검증·재개에 필요한 시간 |
| RPO | 복구 시 허용 가능한 데이터 손실 시점 |

```text
마지막 복구 가능 데이터 시점 ── 사고 ── IT 복구 ── 업무 재개
             ← RPO →       ← RTO →← WRT →
                            사고부터 업무 재개까지 ≤ MTD
                            일반적으로 RTO + WRT ≤ MTD
```

RTO는 **시간**, RPO는 **데이터 시점**이다. 값이 짧을수록 비용이 증가한다. BIA 결과를 바탕으로 전략을 선택하고, 계획에는 발동 기준·권한·연락망·대체업무·복귀절차를 포함하며 정기 시험 후 개선한다.

**BCP 수립 5단계**

1. 범위·정책·조직·일정 등 사업연속성 기획.
2. BIA로 핵심업무, 중단 영향, MTD·RTO·RPO, 필요한 인력·시설·시스템·외부 의존성 도출.
3. 요구 목표와 비용을 비교해 연속성·복구전략 선정.
4. 비상대응·업무연속·재해복구·원상복귀 절차와 연락망을 계획으로 작성.
5. 교육·훈련·시험·검토·변경관리로 수행하고 유지·개선.

### 5.3.4 [P1] 복구센터 비교

| 유형 | 준비 상태 | 복구 특성 | 비용 |
|---|---|---|---|
| Mirror | 운영센터와 거의 실시간 동기·동시 수준 | 즉시 또는 매우 짧음 | 최고 |
| Hot | HW·NW·SW·데이터를 상시 준비 | 수시간 수준 | 높음 |
| Warm | 일부 장비·통신 준비, 데이터·설정 추가 필요 | 수일 수준 | 중간 |
| Cold | 공간·기반시설 중심, 장비·데이터 반입 필요 | 수주 이상 가능 | 낮음 |

정확한 복구시간은 조직 설계와 계약에 따라 달라지므로 유형 이름만으로 고정 수치를 단정하지 않는다. 요구 RTO/RPO, 거리·공통재해, 통신·인력, 비용을 함께 평가한다.

**[답안] 미러사이트**

- 장점: 거의 실시간으로 복제하므로 RTO가 매우 짧고 RPO·데이터 손실을 최소화한다.
- 단점: 구축·통신·운영비와 복제 부하가 가장 크다. 오류·랜섬웨어까지 동기화되거나 두 센터가 공통재해에 노출될 수도 있다.

### 5.3.5 [P1] 백업 전략

| 방식 | 매회 백업 | 복원에 필요한 세트 | 특징 |
|---|---|---|---|
| 전체 | 전체 데이터 | 최신 전체 1개 | 백업 느림·복원 단순 |
| 증분 | 직전 백업 후 변경분 | 전체+이후 모든 증분 | 백업 빠름·복원 복잡 |
| 차등 | 최신 전체 후 변경분 | 전체+최신 차등 | 둘의 절충 |

- `3-2-1`: 데이터 3개 사본, 2종 매체, 1개 외부 보관을 기본 원칙으로 이해한다.
- 운영계정 탈취와 랜섬웨어를 고려해 오프라인·불변(immutable)·논리적으로 격리된 사본을 둔다.
- 백업 성공 로그만 보지 않고 실제 복구시험으로 무결성·RTO/RPO·절차·권한을 검증한다.
- 보존기간, 암호화, 키 분리, 폐기, 소산 장소의 공통재해 위험을 관리한다.

**[답안]** 백업은 데이터 사본 확보이고 재해복구는 사람·시스템·네트워크·절차를 포함한 서비스 복원이다. 따라서 백업 성공 여부뿐 아니라 격리 사본과 정기 복구시험으로 복구 가능성을 검증해야 한다.

## 5.4 [P1] 침해사고 대응·디지털 포렌식

### 5.4.1 [P1] 국내 침해사고 대응 7단계

```text
사고 전 준비 → 사고 탐지 → 초기 대응 → 대응 전략 체계화
→ 사고 조사 → 보고서 작성 → 복구 및 재발방지
```

| 단계 | 핵심 활동 |
|---|---|
| 사고 전 준비 | 정책·조직·연락망·도구·훈련·백업·증거절차 마련 |
| 사고 탐지 | 이벤트 수집, 사고 여부·원인·범위·영향·심각도 판단 |
| 초기 대응 | 증거 보존, 사고대응팀 소집·관련 부서 통지, 임시 조치 |
| 대응 전략 체계화 | 영향 평가, 대응 우선순위·격리·외부 협력 방향 결정 |
| 사고 조사 | 원인·침해 경로·피해 범위·잔존 위협을 분석 |
| 보고서 작성 | 사고 경위·원인·대응·복구 결과와 개선사항을 기록·보고 |
| 복구 및 재발방지 | 검증된 백업·정상 이미지로 복구하고, 취약점·통제·정책·훈련을 개선 |

**기출 복원 표현과 답안 표기**

- 2021년 1회 실기 복원은 마지막 단계를 `해결`로 표기한다. 이는 해당 복원 문항의 표현으로 보존한다.
- 학습 답안에서는 마지막 단계를 **복구 및 재발방지**로 풀어 쓴다. 복구만 하고 원인·통제 개선을 생략하지 않기 위해서다.
- 문제에서 단계명이나 보기로 `해결`을 제시하면 그 문제의 표현을 따른다.

**[참고] NIST SP 800-61 Rev.2를 명시한 문제의 4단계**

```text
Preparation → Detection and Analysis
→ Containment, Eradication, and Recovery → Post-Incident Activity
```

국내 7단계와 NIST Rev.2 4단계는 섞어 쓰지 않고, 문제에서 제시한 체계를 따른다.

단계 수만 통암기하지 않는다. 문제에 제시된 체계를 따르되 증거보존·확산 억제·원인 분석·검증 복구·재발방지가 빠지지 않게 쓴다.
- 이벤트는 관찰된 현상, 사고는 보안정책 위반·CIA 훼손 등 대응이 필요한 사건이다.
- 심각도는 자산 중요도, 데이터 종류·규모, 확산성, 업무영향, 법적 신고 의무로 정한다.
- 즉시 전원을 끄거나 파일을 삭제하면 휘발성 증거와 원인 규명 기회를 잃을 수 있다. 인명·확산·업무 위험과 증거보전을 함께 판단한다.
- 내부 보고와 법정 신고는 별도다. 개인정보 유출은 5.7.7의 통지·신고 요건을 적용한다.

**[답안]** 먼저 피해 범위와 심각도를 분석하고 네트워크 분리·계정 차단 등으로 확산을 억제한다. 증거를 적법하게 보존한 뒤 원인을 제거하고 검증된 백업으로 복구하며, 강화 모니터링과 사후분석으로 재발방지 대책을 반영한다.

### 5.4.2 [P1/P2] Cyber Kill Chain과 MITRE ATT&CK

**[P1] Cyber Kill Chain**은 공격자가 목표를 달성하기까지의 진행을 시간 순서로 설명한다.

```text
정찰(Reconnaissance) → 무기화(Weaponization) → 전달(Delivery)
→ 취약점 악용(Exploitation) → 설치(Installation)
→ 명령·제어(Command and Control, C2) → 목적 달성(Actions on Objectives)
```

**[P2] MITRE ATT&CK 비교·활용**

| 구분 | Cyber Kill Chain | MITRE ATT&CK |
|---|---|---|
| 핵심 관점 | 공격 진행의 7단계 시간 축 | 실제 공격자의 전술(Tactics)·기술(Techniques) 지식 기반 |
| 사용 목적 | 공격이 어느 단계까지 진행됐는지 파악하고 앞 단계에서 차단 | 관찰된 행위를 기술 단위로 분류하고 탐지·대응 공백 식별 |
| 주의점 | 모든 공격이 항상 선형으로 한 번씩만 진행되는 것은 아님 | 고정된 7단계 순서나 단일 공격 절차가 아님 |

- 사고대응 절차는 조직이 사고를 처리하는 방어자 관점이고, Kill Chain은 공격 진행을 보는 공격자 생명주기 관점이다.
- 정찰·전달 단계에서는 공격표면 축소와 메일·웹 통제, 악용·설치 단계에서는 패치·EDR·실행통제, C2·목적 달성 단계에서는 DNS/프록시·egress 탐지, 계정·데이터 접근 통제를 연결한다.
- ATT&CK는 탐지 로그와 통제를 technique에 mapping하여 미탐 영역과 대응 우선순위를 찾는 데 사용한다. tactic 수처럼 변경될 수 있는 세부 수치보다 `Tactics × Techniques` 구조와 Kill Chain과의 차이를 우선한다.

**[답안]** Cyber Kill Chain은 정찰부터 목적 달성까지 공격 진행을 7단계로 나타낸 시간 축이고, MITRE ATT&CK는 실제 공격자의 전술과 기술을 체계화한 지식 기반이다. 전자는 차단 시점을, 후자는 관찰된 행위와 탐지·대응 공백을 분석하는 데 활용한다.

### 5.4.3 [P1] 디지털 포렌식 원칙

디지털 포렌식은 전자적 증거를 적법하게 식별·수집·보존·분석·해석·보고하여 무결성과 법적 증거능력을 확보하는 절차와 기술이다.

| 원칙 | 의미 |
|---|---|
| 정당성/적법성 | 법적 권한과 적법한 절차에 따라 수집 |
| 무결성 | 수집 이후 증거가 변경되지 않았음을 보장 |
| 재현성 | 동일 조건·방법으로 동일 결과를 확인 가능 |
| 신속성 | 휘발·변경되기 전에 적시에 확보 |
| 연계보관성 | 발견부터 법정 제출까지 인수인계·보관 경로를 추적 |

무결성은 원본 쓰기방지, bit-stream image, 수집 전후 hash, 봉인·안전보관으로 입증한다. Hash가 같다는 사실만으로 수집의 적법성이나 분석 결론까지 자동 입증되지는 않는다.

### 5.4.4 [P1] 증거 수집·분석 절차와 CoC

```text
준비·권한확인 → 현장보존 → 식별 → 수집/획득 → 포장·운반·보관
→ 검증 → 분석 → 해석 → 보고·제출
```

- 휘발성 순서는 일반적으로 CPU register/cache, memory·process·network state, 임시파일, disk, 원격·보관매체 순으로 고려한다. 사건과 시스템 상태에 따라 조정한다.
- Live Forensics는 실행 중 메모리·프로세스·연결을 확보하지만 시스템을 변경할 수 있다.
- Dead Forensics는 전원을 끈 저장매체를 write blocker로 획득해 변경을 줄이지만 휘발성 정보는 잃는다.
- Chain of Custody에는 사건·증거 식별자, 수집자, 일시·장소, 획득방법·도구, hash, 봉인상태, 모든 인계자·인수자·시간·목적·보관장소를 기록한다.
- 분석은 복제본에서 수행하고 원본은 봉인·보존한다. 도구 버전·명령·시간대·가정·한계를 보고서에 남긴다.

### 5.4.5 [P2] 포렌식 유형과 Anti-Forensics

| 유형 | 대표 대상 |
|---|---|
| Disk/File-system | 삭제파일, metadata, timeline, slack |
| Memory | process, injected code, key, connection |
| Network | packet, flow, session, IDS log |
| Mobile/Cloud | app data, device artifact, provider log·API |

Anti-Forensics는 secure deletion, 암호화, timestamp 조작, log 삭제, steganography 등으로 수집·분석을 어렵게 한다. 중앙·원격 로그, 시간동기화, 변경방지 저장소, 다중 출처 상관분석으로 대응한다.

## 5.5 [P1/P2] 정보보호·개인정보보호 인증제도

### 5.5.1 [P1] ISMS와 ISMS-P

- **ISMS**: 정보보호 관리체계 인증. 인증기준 영역 1+2를 적용한다.
- **ISMS-P**: 정보보호 및 개인정보보호 관리체계 인증. 영역 1+2+3을 적용한다.
- 인증은 일정 시점의 제품 검사만이 아니라 조직이 위험을 관리하고 통제를 지속 운영하는지를 심사한다.

| 영역 | 분야 | 인증기준 | 핵심 |
|---|---:|---:|---|
| 1. 관리체계 수립 및 운영 | 4 | 16 | 기반 마련·위험관리·운영·점검개선 |
| 2. 보호대책 요구사항 | 12 | 64 | 정책·인적·외부자·물리·기술·사고·재해복구 |
| 3. 개인정보 처리 단계별 요구사항 | 5 | 21 | 수집→보유·이용→제공→파기→권리보호 |
| **ISMS-P 합계** | **21** | **101** | **16+64+21** |

> ISMS는 1+2영역인 80개, ISMS-P는 101개다. 과거 102개 기출 답을 현행 문제에 그대로 쓰지 않는다.

인증 흐름은 `신청·준비 → 심사 → 보완조치 → 인증위원회 심의·의결 → 인증서 발급 → 사후관리·갱신`으로 이해한다. 유효기간은 **3년**이며 유효기간 중 **연 1회 이상** 사후관리를 받는다.

**[P2] ISMS 의무대상 핵심**

- 법정 범위의 전기통신사업자·정보통신서비스 제공자 중 ISP·집적정보통신시설(IDC) 사업자 등 대상.
- 정보통신서비스 부문 전년도 매출액 **100억원 이상**.
- 전년도 일일평균 정보통신서비스 이용자 **100만명 이상**.
- 전년도 매출액 또는 세입 **1,500억원 이상**이면서 상급종합병원 또는 재학생 1만명 이상 학교 등 법정 대상.

의무대상의 세부 업종·예외·산정법은 시행령 개정 가능성이 있으므로 사례 조건을 조문과 대조한다. ISMS 의무대상이라고 자동으로 ISMS-P 전체 3영역 의무대상이라고 단정하지 않는다.

### 5.5.2 [P2] ISO/IEC 27001·CC·KCMVP

| 제도 | 대상 | 무엇을 증명하는가 |
|---|---|---|
| ISO/IEC 27001 | 조직의 ISMS | 국제표준 요구에 맞는 관리체계 수립·운영 |
| ISMS-P | 국내 조직의 정보보호·개인정보 관리체계 | 국내 법·고시에 따른 관리체계 적합성 |
| CC(ISO/IEC 15408) | IT 제품·시스템 | 보안기능 요구와 평가보증 수준에 따른 평가 |
| KCMVP | 암호모듈 | 국가·공공 분야에 쓰이는 암호모듈의 안전성·구현 적합성 검증 |

- CC의 EAL1~EAL7은 **평가보증의 깊이·엄격성** 수준이지 공격을 절대 막는 성능 점수가 아니다.
- PP는 제품군 공통 보안요구, ST는 평가대상 제품의 구체적 보안목표, TOE는 평가대상이다.
- KCMVP와 CC는 대상·목적이 다르며 한 인증이 다른 인증을 자동 대체하지 않는다.

## 5.6 [P1/P2] 정보보호 윤리·법제

### 5.6.1 [P1] 법규 사례를 푸는 순서

```text
행위 시점의 시행 법령 확인
→ 적용 주체·대상 정보·행위 식별
→ 원칙적 금지/허용 판단
→ 동의·법률근거·예외 요건 확인
→ 통지·신고·기록·보호조치·기한 제시
```

법률-시행령-시행규칙-고시의 위계를 구분하고, 같은 주제라도 일반법·특별법과 적용대상을 확인한다. 답안에는 조문 번호를 틀리게 쓰는 것보다 정확한 의무 주체·요건·행위·기한·조치를 쓰는 것이 안전하다.

### 5.6.2 [P1] 정보통신망법

시험에서는 다음 행위 유형을 구별한다.

- 정당한 접근권한 없이 또는 허용 범위를 넘어 정보통신망에 침입.
- 타인의 정보를 훼손하거나 타인의 비밀을 침해·도용·누설.
- 악성프로그램을 전달·유포.
- 대량 신호·데이터로 장애를 발생시키는 행위.
- 침해사고 발생 시 원인분석·피해확산 방지·복구와 법정 대상자의 신고 의무.

**집적정보통신시설(IDC) 사업자**

- 타인의 정보통신서비스 제공을 위해 집적된 정보통신시설을 운영·관리하는 자다.
- 시설의 안정적 운영을 위한 보호조치를 한다.
- 멸실·훼손·운영장애 피해배상을 위해 법이 정한 보험·공제 등에 가입한다.
- 보호조치 이행점검과 시정명령의 대상이 될 수 있다.

과거 정보통신망법의 개인정보보호 조항 상당수는 개인정보보호법으로 이관되었다. 개인정보 수집·이용·유출 문제를 무조건 정보통신망법으로 답하지 않는다.

**침해사고 신고와 자료보전**

- 법률: 정보통신서비스 제공자는 침해사고 발생 시 과학기술정보통신부장관이나 KISA에 **즉시 신고**한다.
- 시행령: 사고를 인지한 때부터 **24시간 이내** 신고하고, 추가 확인 사항도 확인한 때부터 24시간 이내 보완한다.
- 자료보전: 모든 대상자의 자동·상시 의무가 아니다. 과학기술정보통신부장관이 법에 따라 보전을 명한 경우의 의무로 구분한다.

### 5.6.3 [P2] 정보통신기반 보호법

- 중앙행정기관의 장은 소관 분야의 중요 시설을 주요정보통신기반시설로 지정한다.
- 실제 기반시설을 관리하는 관리기관은 지정 후 6개월 이내(승인을 받은 경우 9개월 이내) 취약점 분석·평가를 하고, 이후 매년 수행하여 보호대책을 수립·시행한다.
- 침해사고 발생 시 관계기관과 협력해 신고·복구·확산방지를 수행한다.
- 핵심 구분은 **일반 정보시스템 보안**이 아니라 국가·사회적으로 중요한 기반시설의 보호체계다.

### 5.6.4 [P2] 전자서명법·저작권·윤리

- 전자서명은 전자문서에 첨부·결합되어 서명자의 신원과 서명 사실을 나타내는 전자적 정보다.
- 전자서명이라는 이유만으로 효력이 부인되지 않으며, 법령·당사자 약정이 요구하는 요건을 충족하는지 판단한다.
- 서명 생성·검증과 PKI 기술은 4장, 인증업무의 준수·법적 효력은 이 장의 범위다.
- 저작권의 기술적 보호조치를 무력화하거나 권리관리정보를 제거하는 행위는 별도 법적 문제가 될 수 있다. DRM은 접근·이용 조건을 기술적으로 통제하지만 저작권 자체를 발생시키는 제도는 아니다.
- 사이버 명예훼손·모욕·스토킹·사기·불법정보 유통은 행위와 적용 법률이 다르므로 “사이버범죄” 한 단어로 끝내지 않는다.
- 윤리 원칙: 필요한 권한만 사용, 목적 외 열람 금지, 비밀 유지, 취약점의 책임 있는 보고, 로그·증거 조작 금지, 이해상충 공개.

## 5.7 [P1/P2] 개인정보보호법·안전성 확보조치

### 5.7.1 [P1] 정의와 처리원칙

| 구분 | 핵심 정의·판단 |
|---|---|
| 개인정보 | 살아 있는 개인에 관한 정보로, 단독 또는 다른 정보와 쉽게 결합해 개인을 알아볼 수 있는 정보와 가명정보 |
| 가명정보 | 추가정보 없이는 특정 개인을 알아볼 수 없도록 가명처리한 개인정보; 법 적용 대상 |
| 익명정보 | 합리적인 시간·비용·기술을 고려해도 개인을 더 이상 알아볼 수 없는 정보; 개인정보보호법 적용 제외 |
| 민감정보 | 사상·신념, 노조·정당, 정치적 견해, 건강·성생활, 유전·범죄경력·생체인식·인종/민족 등 |
| 고유식별정보 | 주민등록번호·여권번호·운전면허번호·외국인등록번호 |

개인정보 처리 8원칙의 핵심은 `목적 명확화·최소수집·목적 내 처리·정확성/최신성·안전관리·공개/권리보장·사생활 침해 최소화·책임성`이다. 목적 달성이 가능하면 익명 또는 가명처리를 우선 고려한다.

### 5.7.2 [P1] 수집·이용과 최소수집

개인정보 수집·이용의 법정 근거는 다음 7개로 구분한다. 동의에만 의존하지 말고 적용 근거를 먼저 식별한다.

1. 정보주체의 동의.
2. 법률의 특별한 규정 또는 법령상 의무 준수에 불가피.
3. 공공기관이 법령 등에서 정한 소관업무 수행에 불가피.
4. 정보주체와의 계약 이행 또는 계약 체결 과정에서 정보주체의 요청에 따른 조치를 이행하기 위해 필요.
5. 정보주체 또는 제3자의 급박한 생명·신체·재산 이익을 위해 명백히 필요.
6. 처리자의 정당한 이익 달성에 필요하고 정보주체의 권리보다 명백히 우선하며 상당한 관련성·합리적 범위에 해당.
7. 공중위생 등 공공의 안전과 안녕을 위해 긴급히 필요.

동의를 받을 때 알릴 핵심 4항목:

1. 수집·이용 목적
2. 수집 항목
3. 보유·이용 기간
4. 동의 거부권과 거부 시 불이익의 내용

- 목적에 필요한 최소한만 수집하고 최소수집 입증책임은 처리자에게 있다.
- 필요 최소 정보 외의 수집에 동의하지 않았다는 이유로 서비스 제공을 거부해서는 안 된다.
- 민감정보·고유식별정보는 일반 개인정보 동의와 **별도 동의** 또는 법령상 근거가 필요하다.
- 주민등록번호는 동의만으로 처리할 수 없고 법률·대통령령 등 법정 요건을 확인한다.
- 14세 미만 아동의 개인정보 처리 동의는 법정대리인의 동의를 받고 법정대리인 확인에 필요한 최소정보만 요구한다.

### 5.7.3 [P1] 제3자 제공·목적 외 처리·위탁

제3자 제공 동의의 고지 5항목:

1. 제공받는 자
2. 제공받는 자의 이용 목적
3. 제공 항목
4. 제공받는 자의 보유·이용 기간
5. 동의 거부권과 거부 시 불이익

| 구분 | 판단 기준 | 핵심 의무 |
|---|---|---|
| 제3자 제공 | 제공받는 자 자신의 목적을 위해 처리 | 제공 법적근거·동의, 목적·항목 제한 |
| 처리위탁 | 위탁자의 업무 목적을 대신 수행 | 문서화, 공개, 수탁자 교육·감독, 재위탁 관리 |
| 목적 외 이용·제공 | 최초 목적 범위를 벗어남 | 법정 예외 또는 별도 동의, 최소범위·기록 |

이름을 “위탁”이라고 붙여도 수령자가 독자 목적·결정권을 가지면 제3자 제공일 수 있다. 실질을 본다.

### 5.7.4 [P1] 가명정보

- 통계작성, 과학적 연구, 공익적 기록보존 목적이면 정보주체 동의 없이 가명정보를 처리할 수 있다.
- 가명정보와 추가정보는 분리 보관하고 접근권한·보호조치를 적용한다.
- 서로 다른 처리자 간 결합은 지정 결합전문기관을 통해 수행한다.
- 특정 개인을 알아보기 위한 처리(재식별)를 금지하며, 식별 가능 정보가 생기면 처리를 중지하고 회수·파기한다.
- 가명정보는 개인정보이므로 “자유 이용 가능”이 아니다. 익명정보와 구분한다.

### 5.7.5 [P1] 보유·파기와 정보주체 권리

- 보유기간 경과 또는 목적 달성 등 불필요해지면 지체 없이 파기한다. 다른 법령 때문에 보존하면 분리 보관하고 목적 외 이용을 막는다.
- 전자파일은 복원이 곤란한 방법으로, 종이·매체는 파쇄·소각 등으로 파기한다.
- 정보주체는 열람, 정정·삭제, 처리정지, 동의 철회 등 법정 권리를 행사할 수 있다. 다른 법령상 보존의무 등 제한 사유가 있으면 그 근거와 불복·이의 방법을 알린다.
- **[P2]** 법정 대상·요건에서는 개인정보 전송요구권과 완전히 자동화된 결정에 대한 거부·설명 요구권도 구분한다. 모든 처리자·모든 결정에 무조건 동일하게 적용된다고 단정하지 않고 해당 조문과 시행 범위를 확인한다.
- 개인정보 처리방침에는 처리 목적·항목·기간, 제3자 제공·위탁, 파기, 권리행사, CPO, 안전성 확보조치, 구제방법 등 법정 사항을 공개하고 변경 이력을 관리한다.

### 5.7.6 [P1] CPO·PIA

**개인정보 보호책임자(CPO) 주요 업무**

- 개인정보 보호계획 수립·시행, 처리 실태·관행의 정기 조사·개선.
- 불만처리·피해구제, 유출·오남용 방지 내부통제.
- 교육계획, 개인정보파일 보호·관리·감독, 처리방침 수립·변경.
- 관련 자료 관리와 불필요 개인정보의 파기.

**개인정보 영향평가(PIA)**는 개인정보파일 운용으로 정보주체 권리 침해 우려가 큰 경우 위험요인을 사전에 분석하고 개선방안을 도출하는 절차다. 공공기관은 법정 대상 개인정보파일을 운용하려면 영향평가를 수행해 결과를 위원회에 제출한다.

```text
평가대상·처리흐름 → 법적 근거·위험 식별 → 가능성·영향 평가
→ 개선대책·잔여위험 → 이행점검
```

공공기관의 의무 영향평가 대상 개인정보파일은 다음 중 하나다.

- 5만명 이상의 민감정보 또는 고유식별정보를 처리하는 파일을 구축·운용·변경.
- 다른 개인정보파일과 연계한 결과 50만명 이상의 개인정보가 포함.
- 100만명 이상의 개인정보파일을 구축·운용·변경.
- 이미 영향평가를 받은 파일의 검색체계 등 운용체계를 변경하는 경우(변경 부분).

**기출형 영향평가 고려사항 5개**

1. 처리하는 개인정보의 수
2. 개인정보의 제3자 제공 여부
3. 정보주체의 권리를 침해할 가능성과 위험 정도
4. 민감정보 또는 고유식별정보의 처리 여부
5. 개인정보 보유기간

**기출형 위험도 산정 예시**

```text
위험도 = 자산 가치(영향도) + (침해요인 발생가능성 × 법적 준거성) × 2
```

> 개인정보 영향평가 수행안내서가 제시한 산정 **예시**다. 영향평가 기관은 합리적이고 실질적 위험을 나타내는 다른 방법론을 사용할 수 있으므로 모든 위험평가의 유일한 공식으로 확대하지 않는다.

### 5.7.7 [P1] 개인정보 유출 통지·신고

**정보주체 통지**: 유출을 알게 된 때부터 **72시간 이내** 다음을 통지한다.

1. 유출된 개인정보의 항목
2. 유출 시점과 경위
3. 피해 최소화를 위해 정보주체가 할 수 있는 방법
4. 처리자의 대응조치와 피해구제 절차
5. 신고·문의 담당부서와 연락처

**위원회 또는 전문기관 신고**도 해당 사실을 알게 된 때부터 **72시간 이내**이며, 다음 중 하나면 대상이다.

- 1천명 이상 정보주체의 개인정보 유출
- 민감정보 또는 고유식별정보 유출
- 개인정보처리시스템 또는 개인정보취급자가 개인정보 처리에 이용하는 정보기기에 대한 외부의 불법적 접근에 의한 유출

**[P2] 통지·신고의 예외 처리**

- **선통지**: 유출 항목(1호) 또는 시점·경위(2호)가 확인되지 않았어도 유출 사실, 현재 확인된 내용과 3~5호를 먼저 통지하고 나머지는 확인 즉시 알린다.
- **통지 지연**: 긴급한 확산방지·회수·삭제 또는 천재지변 등 부득이한 사유가 있으면 사유 해소 후 지체 없이 통지한다.
- **게시로 갈음**: 연락처를 알 수 없는 등 정당한 사유가 있으면 대표 홈페이지에 30일 이상 게시한다. 홈페이지가 없으면 사업장 등의 보기 쉬운 장소에 30일 이상 게시한다.
- **선신고**: 유출 항목(1호) 또는 시점·경위(2호)를 72시간 안에 확인하기 어려우면 유출 사실, 현재 확인된 내용과 3~5호를 먼저 신고하고 확인 즉시 보완한다.
- **신고 지연·면제**: 천재지변 등 부득이한 사유가 해소된 뒤 지체 없이 신고한다. 유출 경로 확인과 회수·삭제 등으로 권익침해 가능성이 현저히 낮아졌다면 시행령 요건에 따라 신고가 면제될 수 있다.
- 통지는 정보주체 보호, 신고는 감독기관 대응이라는 목적이 다르므로 서로 대체하지 않는다.

- 원칙: **1년 이상**.
- 다음 중 하나면 **2년 이상**: ① 5만명 이상 정보주체를 처리하는 시스템, ② 고유식별정보 또는 민감정보를 처리하는 시스템, ③ 전기통신사업법상 등록·신고한 기간통신사업자인 개인정보처리자.
- 접속기록과 개인정보 다운로드 상황을 확인·점검할 **주기·방법·사후조치 절차**를 내부 관리계획에 정해 이행하고, 위·변조·도난·분실을 방지한다.

> 접속기록 보존기간과 접근권한 부여·변경·말소 이력 보존기간을 섞지 않는다. 오래된 기출의 “월 1회 점검”을 모든 사례의 유일한 답으로 기계 적용하지 말고, 현행 고시의 위험기반 점검계획 요구를 쓴다.

### 5.7.9 [P1] 고정형·이동형 영상정보처리기기

**고정형 CCTV**

- 공개된 장소에서는 다음 법정 예외 중 하나에 해당할 때 설치·운영한다.
  1. 법령이 구체적으로 허용한 경우
  2. 범죄 예방·수사
  3. 시설안전·관리·화재예방
  4. 교통단속
  5. 교통정보 수집·분석·제공
  6. 촬영된 영상정보를 저장하지 아니하는 경우로서 대통령령으로 정하는 경우
- 설치 목적·장소·촬영범위·시간·관리책임자 등을 포함한 안내판을 알아보기 쉽게 설치한다.
- 목적과 무관한 곳을 비추거나 임의조작하지 않고, 녹음 기능을 사용하지 않는다.
- 운영·관리 방침, 접근권한, 열람·제공 기록, 보관기간 경과 시 파기를 관리한다.

**비공개 장소의 고정형 CCTV**

- 사내 제한구역처럼 불특정 다수가 자유롭게 출입하지 못하는 장소는 공개장소인지 실제 이용관계로 판단한다.
- 비공개 장소라면 제25조의 공개장소 설치 제한이 아니라 개인정보보호법 제15조의 일반 수집·이용 근거를 확보한다.
- 적법한 근거가 있어도 목적 제한, 안내·투명성, 접근권한, 안전성 확보조치, 운영관리, 열람·제공 기록을 적용한다.

**이동형 영상정보처리기기**

- 사람이 신체에 착용 또는 휴대하거나 이동 가능한 물체에 부착·거치되어 사람 또는 사물의 영상을 촬영하거나 이를 유·무선망으로 전송하는 장치다.
- 업무 목적으로 공개된 장소에서 개인 또는 그와 관련된 사물을 촬영하는 것은 원칙적으로 제한된다. 다음 중 하나일 때 허용된다.
  1. 개인정보보호법 제15조제1항 각 호의 처리 근거가 있는 경우
  2. 촬영 사실을 명확히 표시했고, 정보주체가 거부하지 않았으며, 권리를 부당하게 침해할 우려 없이 합리적 범위인 경우
  3. 이에 준하는 대통령령상 사유가 있는 경우
- 허용 사유가 있어도 불빛·소리·안내판 등으로 촬영 사실을 표시·고지하고 목적 제한·안전조치·권리보장을 적용한다.
- 목욕실·화장실·발한실·탈의실 등 사생활을 현저히 침해할 우려가 있는 장소 내부 촬영은 금지한다. 다만 범죄·화재·재난 등에서 인명 구조·구급을 위한 대통령령상 예외를 구분한다.

> 2026-09-11 시행 예정 개정 조항은 이번 제2회 시험일 이후다. 이 시험 답안에는 시험일 당시 시행 중인 조문을 적용한다.

### 5.7.10 [P1] 생체정보 보호

- 생체인식정보는 개인 식별 목적으로 신체적·생리적·행동적 특징에서 기술적으로 생성한 정보이며 민감정보에 해당한다.
- **비례성**: 처리 편익과 개인정보 침해 위험을 비교해 활용 필요성과 범위를 판단한다.
- **적법성**: 수집·이용·제공 등 처리 근거가 적법하고 명확해야 한다.
- **목적제한**: 동의받거나 정당화된 인증·식별 목적 밖으로 무단 활용하지 않는다.
- **투명성**: 처리 목적·항목·보유기간·보호방법 등 보호 사항을 알기 쉽게 공개한다.
- **안전성**: 분실·도난·유출·위조·변조·훼손되지 않도록 기술적·관리적·물리적 조치를 한다.
- **통제권 보장**: 열람·정정·삭제·동의철회 등 정보주체가 자신의 생체인식정보를 스스로 통제할 수단을 제공한다.
- 필요성·비례성을 검토하고 가이드가 권고하는 대체 인증수단 제공을 고려하며, 원본보다 특징정보(template)를 분리·암호화해 저장한다.
- 위·변조 탐지, 전송·저장 암호화, 접근권한·접속기록, 보유기간 종료 파기와 유출 대응을 적용한다.
- 변경하기 어려운 특성 때문에 비밀번호보다 유출 후 위험이 장기적이다. 생체만으로 단일 인증요소를 구성하기보다 위험에 따라 다중요소를 적용한다.

## 5.8 [P1] 실전 사례형 답안·체크리스트

### 5.8.1 관리·위험 사례 6문장 틀

1. **정의**: 문제의 핵심 개념을 한 문장으로 규정한다.
2. **자산·업무**: 보호 대상과 중요도를 적는다.
3. **원인**: 위협·취약점·기존 통제의 한계를 구분한다.
4. **평가**: 가능성·영향·법적 요구로 우선순위를 정한다.
5. **조치**: 관리·물리·기술 대책을 예방·탐지·복구로 제시한다.
6. **검증**: 책임자·기한·로그·감사·시험·잔여위험 승인을 쓴다.

### 5.8.2 법규 사례 6문장 틀

1. 적용 시점과 법령을 특정한다.
2. 의무 주체와 개인정보·행위 유형을 특정한다.
3. 원칙적 허용/금지와 법적 근거를 쓴다.
4. 동의·예외·고지 항목·기한을 쓴다.
5. 안전조치·통지·신고·기록·파기를 쓴다.
6. 감독·재발방지·정보주체 권리보장을 쓴다.

### 5.8.3 사고 사례 6문장 틀

```text
탐지·범위분석 → 보고·심각도 분류 → 확산 억제와 증거보존
→ 원인·지속성 제거 → 검증 복구·모니터링 → 법정 통지·신고와 사후개선
```

### 5.8.4 시험 직전 즉답 체크리스트

- [ ] 자산·위협·취약점·위험·통제를 각각 한 줄로 구분한다.
- [ ] 위험관리 절차와 감소·회피·전가·수용을 순서·예시와 함께 쓴다.
- [ ] 위험관리계획의 방법·절차·인력·기간·대상·예산과 자산 그룹핑 목적을 쓴다.
- [ ] 델파이·시나리오·순위결정·확률분포·퍼지행렬의 식별어를 구분한다.
- [ ] `SLE=AV×EF`, `ALE=SLE×ARO`를 단위까지 계산한다.
- [ ] RTO·RPO·MTD·WRT 관계를 그림 없이 설명한다.
- [ ] BCP 5단계와 BIA 산출물, 미러사이트 장단점을 쓴다.
- [ ] 전체·증분·차등 백업의 복원 세트를 구분한다.
- [ ] 사고대응 6단계와 포렌식 5원칙·CoC 항목을 쓴다.
- [ ] `[P1]` Cyber Kill Chain 명칭과 7단계를 순서대로 쓴다.
- [ ] `[P2]` MITRE ATT&CK의 `Tactics × Techniques` 지식 기반을 Kill Chain의 시간 축과 구분한다.
- [ ] CISO 역할 4개를 관리체계·위험·교육훈련·법정조치로 쓴다.
- [ ] IDC 사업자의 정의·보호조치·보험/공제·점검과 침해사고 `즉시 신고/인지 후 24시간 이내`를 구분한다.
- [ ] ISMS-P `3영역·21분야·101개=16+64+21`을 쓴다.
- [ ] 개인정보·가명·익명, 민감·고유식별·주민번호를 구분한다.
- [ ] 수집·이용 동의 4항목과 제3자 제공 5항목을 쓴다.
- [ ] 제3자 제공과 위탁을 목적·감독 기준으로 구분한다.
- [ ] PIA의 법정 대상 4유형·고려사항 5개·기출형 위험도 산정 예시를 구분한다.
- [ ] 유출 통지 5항목, 72시간, 신고 3요건을 쓴다.
- [ ] 접속기록 1년/2년과 2년 요건 3개를 쓴다.
- [ ] CCTV 안내판·목적 제한·녹음 금지를 쓴다.
- [ ] 생체인식정보 보호 6원칙(비례성·적법성·목적제한·투명성·안전성·통제권)을 쓴다.

## 5.10 이 장만 보는 최종 회독 순서

### 1회독: 구조 이해

`5.1 관리체계 → 5.2 위험 → 5.3 통제·BCP → 5.4 사고 → 5.5 인증 → 5.7 개인정보` 순서로 읽는다. 5.6 법제는 5.7의 법 적용법과 연결한다.

### 2회독: P1 백지 재현

1. PDCA·정책체계·CISO 4역할·자산관리.
2. 위험관리 흐름·4대 처리·ALE 계산.
3. RTO/RPO/MTD/WRT·복구센터·백업.
4. 사고대응·Cyber Kill Chain 7단계·포렌식 원칙·CoC.
5. ISMS-P 3영역과 101개.
6. 정보통신망법의 IDC와 침해사고 신고 시점.
7. 개인정보 정의·동의·제공/위탁·가명·PIA·유출·안전조치·CCTV.

### 3회독: 기출을 답안으로 변환

- 단답은 `용어 + 핵심 구별어`까지 쓴다.
- 서술은 `정의 → 원인/요건 → 절차/대책 → 검증`으로 쓴다.
- 계산은 식·대입·단위·결론을 모두 쓴다.
- 법규는 `주체 → 요건 → 행위 → 기한 → 조치`가 빠졌는지 확인한다.
- P2까지 학습할 때는 Kill Chain의 시간 축과 ATT&CK의 `Tactics × Techniques` 지식 기반을 비교한다.

### 최종 완료 기준

- [ ] P1 표와 절차를 자료 없이 80% 이상 재현한다.
- [ ] 위험·BCP·사고·개인정보 사례 각각 1문제를 10분 내 서술한다.
- [ ] 오래된 기출 수치와 2026 현행 수치를 구분한다.
- [ ] 틀린 문제는 이 문서의 해당 절에 연결해 오답 이유를 한 줄로 기록한다.
